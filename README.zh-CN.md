# NeuroForge 神经元搭建器

> English: [README.md](README.md)

> 开发交接：[修复日志](FIX_LOG.md)记录 2026-09-22 审计修复、GPT-6 接入、验证结果及桌面构建状态，继续修改前请先查看。
>
> **GPT-6 Astra**：AI 助手 → 设置 →「OpenAI GPT-6」，填写自己的 OpenAI API Key 后应用。内置 Responses 协议支持聊天、看画面和工程工具调用；真实账户权限可用「测试连接」检查。原有 DeepSeek / 本地模型接口仍可使用。
>
> **切换模型**：AI 助手 → 设置 →「选择模型」，点击「刷新模型列表」后选择当前接口提供的模型，也可手填模型 ID。刷新列表不会自动更换当前模型。OpenAI API 与 ChatGPT／Codex 订阅额度分开计费（[官方说明](https://learn.chatgpt.com/docs/auth)）。

一个工业软件风格的可视化神经网络搭建器。用鼠标在 3D 空间里放神经元、连线、配参数，
然后一键编译成可直接使用的模型文件——不用写代码。

当前状态：**第一阶段原型已完成并验证通过**（992 项交互断言 + 14 项渲染一致性 + 28 项权重块渲染对账 + 19 项分块渲染对账 + 117 项流式载入 + 283 项导入器 + 117 项跨语言容器对拍（含空间分块的逐块对拍、权重块分段、共享参数组的段内引用表与转置共享）+ 25 项流式载入跨语言对拍 + 15 项工程格式兼容性验算，全部通过）。Windows 桌面版已经可用（见「桌面程序」）。

## 桌面程序（Windows）

桌面上的 **NeuroForge** 图标就是它。原生窗口 + 系统标题栏 + 任务栏图标 + 开始菜单 + 卸载入口，
和别的 Windows 软件一样——不是"套一层浏览器"。

| | |
| --- | --- |
| 安装包 | `desktop/src-tauri/target/release/bundle/nsis/NeuroForge_0.1.0_x64-setup.exe`（**1.54 MB**） |
| 装在哪 | `%LOCALAPPDATA%\NeuroForge\`（当前用户，不要管理员权限） |
| 卸载 | 设置 → 应用 → NeuroForge，或 `%LOCALAPPDATA%\NeuroForge\uninstall.exe` |
| 程序本体 | `neuroforge.exe` **3.53 MB**（整份界面打包在里面，运行时**不读仓库**） |
| 内存占用 | 打开默认工程约 **22 MB** |
| 依赖 | 系统自带的 WebView2 运行时（Win11 预装，Win10 21H2 之后绝大多数也有） |

壳子（`desktop/src-tauri/src/main.rs` + `src/io_bus.rs`）补浏览器给不了的四件事，
**界面、渲染、编译、AI 全在页面里跑，壳子不掺和**：

- **真窗口**：任务栏图标、Alt+Tab、窗口标题跟着页面走；
- **导出走原生对话框**：默认落在「文档」，并记住上次的目录。**一个文件**（保存工程 / 存 ONNX / 导出报告）
  弹「另存为」；**一批文件**（编译一次会连出 net.py / model.bin / model.c / build.bat…）只弹
  **一次「选择文件夹」**，整批由桌面程序直接写盘——不走浏览器下载通道，因为同一页面连续自动下载
  会被 Chromium 拦掉（浏览器里会弹「允许下载多个文件」，WebView2 没有这个提示框，实测一批 3 个
  只落得下第 1 个）。重名不覆盖，自动加 `(2)` `(3)`。任何对话框取消了 = 这次导出作废，
  不会偷偷写到某个目录；
- **拖放**：把 `.nforge` 从资源管理器拖进窗口就能打开（Tauri 自带的拖放处理已关掉，走网页原生那套）；
- **原生 I/O 总线**（`src/io_bus.rs`）：通用信号通道里的 **UDP / TCP / 串口**只有桌面版能做，
  页面通过 `nf_io_open / nf_io_send / nf_io_poll / nf_io_close / nf_io_links / nf_io_close_all`
  让壳子开 socket、收发字节（帧走 base64，自写编解码，没引新依赖）；「系统按键」也在这里
  （`send_keys`，`SendInput` 注入到前台窗口，修饰键真按住而不是粘在一起）。浏览器版读不到这些命令，
  对应的通道会**明说打不开**，不会假装能用。

自带自测浏览器和桌面壳跑的是同一份页面、同一套断言：把自测页装进壳子启动，回读到的窗口标题就是
`NFTEST 〈项数〉P/0F`、末尾一行是 `== 〈项数〉 PASS / 0 FAIL ==`（断言数每加一轮功能就往上涨，现在 992）。
断言覆盖 WebGL 渲染、流式载入、撤销、i18n、接口运行时。本轮新加的起步卡片 / 语言自动判定 / 视图栏「分层」，
是先跑满 992 项断言、再在**装好的桌面版里**当场点过看过的。其中一条专门核对 `inShell()` 跟真实环境一致，回读到 `inShell=true __TAURI__=true`，
所以「同一份自测浏览器和桌面壳里都能跑」不是推断出来的。
更早一轮还在壳子里当场跑过一次整批导出：4 个文件只弹一次文件夹选择框、四个都按字节落盘。
整批导出后来又复查了一遍，这次探针是挂在**成品页**尾部打包进壳子的（跑的就是真界面，不是自测页）：
窗口标题回读 `NFPROBE shell=true ui=true`，一次文件夹选择框、4 个文件（2 个文本 + 1 个 Blob +
1 个 Uint8Array）逐字节核对为 `[65,65,65]` / `[66,66,66]` / `[67,67,67,67,67]` / `[68,68,68]`；
再跑一遍得到 `(2)` 后缀，旧文件没被动，确认重名不覆盖。单文件那条路也实测过：`Ctrl+S` →
原生「另存为」→ 回车 → `文档\未命名工程.nforge` 真的落盘。更早一版还探过 DeepSeek 那条链，
窗口标题回读为 `NFTEST <通过数>P/0F  DEEPSEEK http=401`（401 = 通到了服务器、只是没填 Key，CSP 没挡；通过数每版都在涨，这里要看的是那个 http=401）。

**重新构建**（改完界面之后）：

```
node prototype/build_all.mjs             # 完整前端构建：esbuild → 成品页 → 17 个校验页 → 静态复查
cd desktop
npm install                              # 第一次要装 @tauri-apps/cli
npm run build                            # = npm run frontend && node sync_frontend.mjs && tauri build
```

第一次编译要拉几百个 crate（约 10 分钟），之后每次约 1 分钟。**已经装好的那份不会自动更新**——
改完代码要重新 `npm run build`，再跑一次安装包（或直接把 `target/release/neuroforge.exe` 覆盖过去）。

`npm run build` 会自己先把前端完整重建一遍（`npm run frontend` = `node prototype/build_all.mjs`），
再同步进壳子。同步那一步不只是搬文件：它会拿成品页里写着的**源码指纹**跟当前源码逐个文件对哈希
（B16 的修法，见 `prototype/buildinfo.mjs`），对不上就**拒绝打包并指名改了哪个文件** ——
所以「编译成功、界面却是上一版」不会再悄悄发生。只改了前端、暂时不想重打桌面程序时，
单独跑 `node prototype/build_all.mjs`（或 `cd desktop && npm run frontend`）就够了。

### 桌面壳里「内联样式全失效」这个坑（2026-09 修）

壳子用 Tauri 的 CSP。`tauri.conf.json` 里 `style-src` 写的是 `'self' 'unsafe-inline'`，
但 Tauri 打包时会**给内联样式自动补一个 nonce**；按 CSP3 的规矩，同一个指令里只要出现
nonce 或哈希，`'unsafe-inline'` 就被忽略。而 nonce 加不到 style **属性**上 ——
于是整个桌面版把 `style="..."` 全丢了：面板错位、自己画的确认框没有边框和阴影、
弹出来的提示文字被挤成竖排；换成浏览器打开（本地服务不带 CSP）一切正常，
所以光看截图根本发现不了。

症状很好认：`el.getAttribute('style')` 明明写着 `margin:0 0 2px`，
`getComputedStyle(el).margin` 却是 `0px`。抓一下响应头能直接看到
`style-src 'self' 'unsafe-inline' 'nonce-...'`。

修法是只关掉 style-src 这一条的自动改写：

```json
"security": { "csp": "...", "dangerousDisableAssetCspModification": ["style-src"] }
```

`script-src` 那条哈希照旧留着（脚本没这个问题，也别顺手放宽）。实测改完响应头变成
`style-src 'self' 'unsafe-inline'`，`#ai-keynote` 的 margin 回到 `0px 0px 2px`，
`innerHTML` 塞进去的 `<span style="white-space:nowrap">` 也真的 nowrap 了。

> 顺带一条同源的坑：在 WebView2 里，**元素还没进文档时用 `setAttribute('style', ...)` 写样式**，
> 之后只要再走一次 CSSOM（`el.style.display = 'flex'` 这种），整串会被重新序列化，
> 而那时的声明块里只剩 CSSOM 写过的这一条 —— position / z-index / 背景全丢。
> 自己新建的元素一律用 `el.style.cssText = ...`。

## 已实现的功能

**3D 空间编辑**
- 神经元可放在任意空间坐标；**神经元本身不分类型**，靠颜色区分就够了
- 跟外界打交道的那几个用**接口**标记（接收外界信号 / 输出到外界 / 双向），编译时变成模型的输入 / 输出
- 手动连线决定任意拓扑（任意 DAG，不限于规整分层）
- **成环也能编译**：反馈连接、递归、自环都允许——落在同一强连通分量里的边被当成**回边**，编译时读「上一拍」的值，整张图按时间展开（`NUM_STEPS`，默认 8 拍）。详见「循环网」那一节
- 连接按权重正负着色（蓝正 / 红负）、按权重绝对值变粗
- 连线预览、悬停高亮、选中光晕、孤立节点一眼可见
- **选中神经元后，入边与出边分别高亮**（入边青色、出边橙色），一眼看清数据从哪来、到哪去
- 同时淡化其余对象（`显示 → 选中时淡化其他对象`），高亮色与淡化都可一键关闭
- 连线可在**屏幕空间**点击选中：判据是「离鼠标 7 像素以内」，与缩放级别无关
- **视角中心能跟着你走**（不再是「只能盯着原点」）：方向键 `↑↓←→` 平移镜头（按住持续滑行、松手缓停，`Shift` 更快），
  `F` 聚焦选中（没选就框住整张图），`Shift+F` 把旋转中心搬到选中对象上、视距一点不变 —— 之后转就是绕着它们转；
  左栏「相机」那一块有十字方向盘和这两个按钮，勾上「选中就换旋转中心」后，选中谁镜头就围着谁

**两侧面板：每一类都能折叠，放置类跟着工具走**
- 左右两栏的**每一类分区都能点标题收起 / 展开**（左栏：工具模式 / 神经元 / 按坐标放置 / 批量生成 /
  显示 / 流式载入 / 工程统计；右栏：属性、空间坐标、连接、模拟激活、动作……），标题右侧的箭头会跟着转
- 折叠状态**按分区身份记**（左栏用固定标记，右栏的动态标题去掉变化的那段数字）：
  切换选中对象、属性面板整块重建、切换界面语言，都不会把折叠状态弄丢
- 「**神经元 / 按坐标放置 / 批量生成**」只在切到「**放置神经元**（A）」时出现；
  用选择 / 连线 / 删除工具时它们不占地方，左栏只剩下常看的那几块
- **模拟激活的设置搬到了右栏**，和「模拟激活」按钮放在同一块里：播放速度、最多播放波数（含上限说明）、
  把接口也当信号源、运行状态、重播 / 清除——点了按钮就能就地调，不用再横跨两块面板

**颜色：神经元多了也分得清**
- 每个神经元可单独上色（右侧「颜色」），或批量上色
- 批量面板提供：应用指定颜色 / 按选中顺序自动配色（彩虹）/ 随机配色 / 恢复接口色
- **放置面板带「放置颜色」**：勾上之后，新放的神经元自动带上这个颜色，一排一排按颜色铺
- 自定义颜色优先于接口色；取消自定义色即可回到接口色 / 默认色

**按坐标放置**（大规模搭建的主力方式）
- 坐标可直接输入 XYZ，不必用鼠标去摆——手工拖拽放不准，几千个神经元时更不可能
- **每放一个自动沿设定轴步进一格**：步进单位、主步进轴（X / Y / Z）都可设定
- 支持**负步进**，一排可以从右往左、从上往下放
- **排 / 面两种模式**：排模式沿单轴连放一排；面模式每放满「每行数量」个就换第二轴，
  一次填满一个平面（主轴、次轴任选，例如主轴 Z + 次轴 X）
- `Enter` 键等同于「放置」按钮，键盘连按即可快速铺满
- `Shift+点击` 视口可把基准坐标吸附到地面网格；「以选中为基准」直接对齐已有神经元
- 面板实时显示「下一个落点」与「已放个数」，不会放丢

**快捷铺设：一列 / 一面 / 一方**
- 填「数量 X / Y / Z」，一次铺出 `nx × ny × nz` 个规则网格，三轴间距都用「步进单位」
- 「铺一列」= 沿 X 排开；「铺一面」= X × Y 一张平面；「铺一方」= 三轴立体块
- 铺完**原点顺移到这一片之后**，接着铺下一片不会重叠
- 可勾选「铺设后按顺序连成链」，铺完直接得到一条 DAG 链
- 走的是直接写数组的快路（不是一个个 `addNeuron`），几万个也是一次搞定；
  一片超过 20 万个会明确拒绝，不会铺一半

**看规模：按权重看粗细 / 按强度看大小**
- `显示 → 连线粗细按权重`：|权重| 映射到 0.045 ~ 0.99 的圆柱粗细，一眼看出哪些是主要连接
- `显示 → 神经元大小按连接强度`：半径倍数 0.5 ~ 1.9，强度 = 连接数 50% + 权重绝对值和 50%
  （两者各自归一化后相加），一眼看出哪些是汇聚 / 发散的关键神经元
- 归一化用的是**参考区间**，不是除以最大值：大图取 p2~p98，小图（≤ 64 个）直接用极值。
  除以最大值时，一个超大枢纽会把其余几十万个点全压成同一个尺寸，看着就像「点了没反应」
- 下面两个**对比度滑杆**（0.5 ~ 8 倍，默认 1）把挨得近的差别拉开：以中位数为轴，
  `y = 中位数 ± (半边长) × u^(1/倍数)`，两段幂函数，**两端钉死在 0 / 1**。
  1 倍 = 逐位等于照参考区间线性映射（忠实、既不放大也不压缩）；调大则中位数附近的一段
  被拉得越开，真实模型里 |w| 大多挤在很小的一段，就得靠它才分得开；调小（0.5 倍）相反，
  是「都差不多」的粗看。**两端钉住 + 上下两半各自张开**是有意的：`t = 0`（孤立神经元、
  零权重）永远钉在最小值，两半都不会被夹成一个常数。线性放大做不到这点——倍数一大，
  中位数以下那一半会全被夹成同一个最小值，那只是把「看不出区别」换了个地方（回归里有这一条）
- 拖动滑杆**不用松手当场就变**（只重写受影响的球层 / 圆柱层），松手再做一次完整重建对齐
- 代价说清楚：对比度是「放大中位数附近的差距」，放大必然把别处压掉——倍数拉大后，
  **中位数以下会向最小值收拢**（不是变没了，是变得很接近最小）。想排强弱就别拉太大
- 关掉开关时滑杆变灰、拖不动（免得拖了没反应）
- 两者都是**纯显示**：一个字的数据都不改，关掉逐位回到默认值，也不进编译结果
- 开了「粗细按权重」时，中档 LOD 会自动把圆柱层带上——那个档位平时不画圆柱，否则就没粗细可看
- **作用范围跟着框选走**：两个开关**各认各的框选**——大小认「框选的神经元」，粗细只认「框选的连线」；
  哪一类没有框选，那一类就作用于全图（所以框了一堆神经元但没框连线时，粗细仍旧按全图排开）。
  连线框选：空白处拖拽 = 神经元 + 连线一起框；Alt+拖拽 = 只框连线（原先框着的神经元不动）。
  取消框选自动回到全图；提示行会写明当前范围
- 神经元**默认一律一样大**：输入 / 输出接口只用颜色区分（青 = 输入、橙 = 输出、黄绿 = 双向），
  不再顺手画大一点。屏幕上出现的大小差异只可能来自这个开关
- 简档（远看）的点云也按同一套规则分大小：点云改成自绘着色器、按 attribute 调 `gl_PointSize`，
  原来的 `PointsMaterial` 一个材质只能有一个尺寸，远看时开开关等于没反应
- 实例数超过 4 万时，对比度滑杆改成**松手后**整场重算（拖的时候只有提示在动）：
  每拖一格就重写几十万个实例（一次几 MB 上传）不划算，提示行里会写明

**批量连接：框选一片，一次成网**（右侧批量面板，选中 ≥ 2 个神经元时出现）
- **按距离随机连接**：「每个神经元最多出边数」+「最大距离」，在距离内随机挑最近的几个
- **按轴分层连接**：沿所选轴按「层厚度」分桶，每个神经元只连**相邻下一层**最近的几个——常见的前馈连法
- **按轴串联成链**：沿轴排序后相邻相连，永远是一条链
- **删除选中神经元之间的连接**：把这一片内部的边一次清掉（对外连接不动）
- 勾了「只连单向」时按 `(层号, 编号)` 的字典序判方向，**保证不会成环**；
  同层时退化成「只连编号更大的」，所以一片刚放好、还没有任何连接的神经元也能连出边来
- 两两比较是 O(n²)，所以一次最多处理 **4000 个**神经元，超了明确拒绝并让你分批框选
- 已有的边一条不动，重复的自动跳过并计数

**模拟激活的波数上限**（右侧「模拟激活 → 最多播放波数」）
- 0 = 不限；填 N 就播到第 N 波停下——大模型一次点亮几十万个神经元会把电脑拖卡
- 波数从「第一波真的有神经元点亮」开始数，**空波不占额度**（深层模型动辄几百个空波）
- 上限在**计算阶段就截断**，不只是不播——不会白算后面的波；运行中把上限调小也会立刻停

**模型导入**
- `tools/import_model.py` 把 ONNX 模型折成神经元 + 加权边，直接生成 `.nforge` 工程
- `Gemm` / `MatMul` / `Add` / 常用激活 / 形状直通算子都能折；不认识的算子**明确报错并说明原因**，不猜
- 导入后照常编辑、照常编译；导入是单向的（不能导回 ONNX）
- **导入来源表**：折平**之前**那个算子图会连同「折进来的激活 / 权重数 / 折出来是哪些神经元 / 跳过了谁 / 精度在哪儿变过」一起写进工程文件头，右上角「结构视图 ⇄」（`F9`）翻过去就是它
- 坐标与名字一定是**生成**的（ONNX 里没有这两个概念）：形状按拓扑分层铺开（`--layout ring / line / grid`），导入后在界面里还能「直线 / 网格 / 力导向」随时重排
- 确实不需要的算子要显式 `--allow-skip` 才跳，跳过会**逐条记进工程文件**并把工程标成 `exact=false`（数值不再等价于原模型）——不偷偷跳
- **共享参数（同一个权重被多处引用）能表达，而且导入时就是真共享**：导入器把同一个常量折出来的
  **权重块**编成一个**共享参数组**——组里的块共用同一份参数，改一处全组一起变，编译出去只存一份，
  反向传播的梯度累加到同一段上。数值与原模型一致（**不算数值失真**，`exact` 仍然是 true）。
  建成了几组、每组省下多少个权重，终端会打印、来源表里也写着；不想建组用 `--no-tie-blocks`。
- `--report` 把「数值 / 名字 / 坐标 / 结构 / 权值共享 / 部分载入」六类失真整份倒成 JSON，方便进流水线做门禁

**权重块（dense block）：大矩阵不展开成边**

一个 4096×4096 的权重矩阵是 1600 万条边，逐条画出来既画不动也存不下。
所以编辑器把这种"稠密二部图"收成一个**权重块**：一段稠密权重矩阵 + 两端的神经元 id 列表。

- 在视口里选中一批连接 → 批量面板 →「打包成权重块」；只覆盖了区域里一部分位置时
  会**明确报出缺多少个并拒绝打包**（按住 Shift 点、或用「打包（缺口补 0）」才是把这些位置记 0）
- 块在计算上是**一等公民**：编译时变成**一次 `matmul`**（`h[行] × W` 再 `index_add` 到列上），
  模拟激活走同一条路径——所以编辑器里看到的和编译出来的结果一致
- 块的**终点必须唯一**。同一列出现两次，在矩阵乘语义里等于把两行隐式求和，太含糊，直接报错
- 单块上限 **4194304 个权重**（约 2048×2048，16 MB float32），超了提示先切块，不静默截断
- 块的权重可以单独冻结；编译后这些权重会在 autograd 里被挡掉梯度
- 「展开成连接」是编辑块内部具体权重的唯一入口（超过 20 万权重时拒绝展开，免得把界面拖死）
- 块**独立成段**存进 `.nforge` v3，跟神经元分块互不影响；v2 JSON 也能存，
  但权重超过 20 万个时保存会拦下来让你改用 `.nforge`

**权重块在 3D 里怎么显示**

块不是"一堆线"，而是**一张热力图板**：

- 颜色按**正负分**：正权重偏蓝、负权重偏红；亮度按 `|w|` 占该块最大绝对值的比例开方，
  所以小权重也看得见、大权重不会一片死白
- 板子**始终正对相机**（billboard），立在两个神经元团的中间，长宽比跟着 `列数 / 行数` 走
  （比值夹在 0.12 到 8 之间，免得极端形状变成一根针或者一条线）
- 贴图**封顶 96×96 像素**：再大的块也只画这么多，超出的权重在像素内做多采样（总采样预算固定），
  所以"块很大"只影响精度、不影响帧率
- 块默认**压暗显示**（0.84 倍），悬停 / 选中才亮到正常亮度并描一圈边框——一眼看出当前在看哪一块
- 点中板子就选中这个块；**点击优先级是 神经元 → 连线 → 块**，不会因为板子挡住就选不到神经元
- 场景里最多同时画 **1024 个块**，超出的只在右侧「权重块」面板里列出（面板里也能直接选中 / 定位）
- 板子只做到"看得出权重分布"这一步：要看某个具体权重，仍然走「展开成连接」

**参数设置**
- 单个神经元：名称、接口、颜色、激活函数（**11 种**：8 种无状态 + 记忆 / 漏电积分 / 脉冲 3 种有状态）、**激活阈值**、偏置、冻结、XYZ 坐标
- 单条连接：权重、冻结、取反 / 归零
- **拖动数值即时生效**：改坐标 / 改权重时不必等松手、不必按回车，视口里立刻跟着动，
  并在视口顶部弹出实时坐标牌（`#22  X 0  Y 40  Z 0`），拖到哪就看到哪
- **批量设置**：框选或按条件选中一批后，批量改接口 / 颜色 / 激活函数 / **阈值** / 偏置（设为·加·乘）/
  权重（设为·加·乘·随机初始化·Xavier 初始化）/ 冻结 / 平移 / 随机散布 / 删除
- 一条神经元的「选中所属入边 / 出边」可以快速把它的连接捞出来批处理

**模拟激活（带阈值门槛）**
- 选中若干神经元 → 点「模拟激活」，信号按 `Σ(权重 × 上游激活值) + 偏置` 往下传
- **只有达到该神经元激活阈值的才会被激活**；没到阈值的不激活，也不会继续往下传
- 因此：**只选一个神经元时，后面往往推不动**；一次多选几个一起注入，和够了才会级联起来
- 激活顺序**按拓扑波次逐波点亮**（速度可调），越晚被激活的颜色越暖
- **脉冲式高亮：亮一下就淡出，不留常亮状态**。每一波像信号一样"闪过去"，
  闪完自动恢复原色，整个动画结束后自动收工——不会把图糊成一片颜色
- 只有真的"信号流过"的边才会闪；空波次会跳过（深层模型动辄几百波，空波不占时间）
- 状态栏实时显示"第 k / n 波，已点亮 x / y 个神经元"；可一键重播 / 清除
- 实例太多的波次只上色、不做缩放动画，几十万节点的图也能看出信号流向
- 可勾选「把『接收外界信号』的接口也当作信号源」
- **「拍」和「波」是两个数，别混**：波 = 一拍之内按拓扑往下传了几层；拍 = 时间。图里有环、**或者有
  状态型神经元**时按「展开步数」（默认 8）一拍一拍地跑，每拍信号源重新注入、状态接着上一拍往下累。
  报数时分得很清：`activated` / `activatedNodes` 是**不同神经元的个数**，`fired` 是跨拍累加的点亮
  **次数**（多拍的图里它比神经元总数还大，这是正常的），`steps` 是拍数、`span` 是一拍里有多少波。
- 注意：阈值只作用于**编辑器内的模拟激活**，生成的模型是标准加权和 + 激活函数，阈值不写进模型

**整图替换会先问一句**

新建工程 / 打开工程 / 载入示例网络 / 压力测试 / 「生成测试网络」这几条会把当前的图**整个换掉**，
而且撤销历史一起清掉（Ctrl+Z 回不来）。所以人点菜单时先弹一个确认框，框里会告诉你当前有多少神经元 /
多少连接，以及本机自动保存里还有没有一份能找回。空白工程不弹（没什么好丢的）。
**AI 走 `menu` 工具调这几条时不会弹这个框**——它在更早的一步（"大改动先问我"）就已经问过了，
在这儿再弹一个会把人卡住、AI 却以为已经做完了。

**有状态神经元（像生物神经元那样把信号存住）**

编辑器里的激活函数一共 11 种，末尾三种是**有状态**的：值跨拍保留，不是算完就丢。

| id | 名字 | 每拍怎么算 | 什么时候用 |
| --- | --- | --- | --- |
| 8 | 记忆 Memory | `s ← s + Σw·x`（只进不出，永不忘） | 累积器 / 计数器 / 长期保持 |
| 9 | 漏电积分 Leaky | `s ← k·s + Σw·x`（每拍漏掉 1−k） | 有衰减的短期记忆（最像真实膜电位） |
| 10 | 脉冲 LIF | `s ← k·s + Σw·x`；`s ≥ 1` 就发一个 1 出去，然后 `s ← s − 1` | 脉冲神经网络（0/1 输出） |

- **这三类不新增任何参数字段**：原来那个「偏置」格子，对它们就是**保持系数 k**（0~1，1 = 一点都不漏）。
  属性面板里那一格会改名成「保持系数 k」；设成这三类时，空着的 k 会自动补成 0.9。
  `.nforge` 和 `model.bin` 的字节布局一个都没动——老工程照读，旧版软件也照样能打开。
- **激活阈值对它们不生效**（脉冲的发放阈值固定 1.0）：靠 k 控制，不靠阈值。
- 三条编译路都带状态：生成的 PyTorch（`.py`，**直接跑就是带状态的**）和独立可执行（C）都真带；
  **ONNX 没有隐式状态**，导出成 `.onnx` 后膜电位不会保留，编译时会给出明确警告——不静默算错。
- 训练时反传只走**当前这一拍**（状态是 detach 的，等于截断的 BPTT）。要真训长时序得自己改训练代码。
- 编辑器「模拟激活」对它们是一拍一拍算的，波次标签会写成「第 3 拍 · 第 2 波」。
- 实测三条路**逐位一致**：一张「输入 → 记忆 / 漏电积分 / 脉冲」的图跑 8 拍，编辑器模拟、生成的
  torch、gcc 编出来的 exe 都给 `8 / 1.9921875 / 1`。

**渲染细节分档（LOD）——大模型流畅的关键**

圆柱连线每条要 36 个顶点，线段只要 2 个——100 万条连接从 3600 万顶点降到 200 万，差 18 倍。
所以按相机距离自动分三档（也可在 `显示 → 渲染细节` 手动锁死）：

| 档位 | 神经元 | 连线 | 用在什么时候 |
| --- | --- | --- | --- |
| 高 | 实例化球体 | 带粗细的圆柱，权重一眼可见 | 拉近看细节 |
| 中 | 实例化球体 | 细线段，仍按权重上色，只是不画粗细 | 中等距离 |
| 简 | 抽样点云 | 抽样线段 | 拉远看整个模型 |

- 分档依据是「一个神经元在屏幕上占多少像素」，而不是死板的相机距离，
  所以模型本身的尺度差异不会让档位判断失准；小图（≤5000 连接）永远用高档，不做无谓降级
- **简档的绘制量与模型规模解耦**：图再大也只画既定的点数 / 线数（默认 9 万点 + 20 万线），
  所以拉远看整个巨型模型时帧率是稳的
- 远离时是**模糊但可读**的：点云看得出整体形状与颜色分布，细线看得出权重正负与大致连接走向
- 选中的那几条关联边在简档里也会被强制画出来，拉远了也知道自己选的东西连到哪
- 规模兜底：连接 > 60 万时高档自动降为中档，神经元 > 150 万时中档降为简档

**界面语言**
- 右上角 `语言` 菜单可切 中文 / English，**即时生效、无需重启**，选择记在 localStorage
- 没手动选过时**跟着系统语言走**：系统是英文的第一次打开就是英文界面，认不出来就按中文
  （这个软件的主场在国内）。只有在菜单里选过一次，之后才一直按你选的来
- 中文就是源码里的原文，所以中文模式下零开销；英文模式下只有新生成的面板才会被翻译一遍
- 词典在 `src/i18n.js`：键是界面上出现的那段文本，值是英文；查不到就原样返回，
  所以漏翻只会退回中文，不会报错。新增文案时加一条即可
- 注意：英文模式靠一个 MutationObserver 给**新生成**的节点补翻译，所以切回中文时必须把它摘掉，
  否则新写出来的中文文案会被它又翻成英文

**两侧栏收放 + 沉浸模式**
- **收放按钮是贴在面板内边、竖直居中的一条小竖条**（左栏右缘的 `‹`、右栏左缘的 `›`），
  就是大多数软件"边上一小条、点一下就收"的常见做法——不放在面板顶条那种谁也不会去看的地方。
  视图菜单和快捷键 `[` / `]` 是等价的入口；反斜杠一次收起两栏（沉浸模式），再按一次全回来
- 竖条是**挂在视口里的浮层**（`#viewport > #tab-left / #tab-right`），面板整块 `display:none` 之后
  按钮照样钉在边上；收起时列宽**归 0、完全不占宽度**（不是留一条 20px 的窄边）。
  换来的是"收起来之后按钮跟着消失、再也找不回来"这件事不会发生
- 箭头方向也跟着变：展开时指向要收回去的那边，收起时指向拉出来的那边
- 底部 AI 框用的是同一套做法，只是转了 90°：横在对话框**顶边**正中的小横条（`#viewport > #aiwrap > #tab-ai`），
  摊开时它贴在对话框顶上，收起来时 AI 框整块让位、它自己落回视口底边——所以它永远不会消失，
  AI 框故意没有"关掉"键，靠的就是这条小横条
- 面板在收起态是整块 `display:none`，所以不参与布局、也不吃渲染
  （代价：三列的列位必须显式钉住——列位一乱，自动排布会把视口塞进别的列去）
- 选择记在 localStorage，下次打开还是上次的样子；`NF.setPanels({left:false,right:false})` 也能脚本控制

**底部 AI 助手（用说话的方式操作编辑器）**
- 视口底部中间挂一个小对话框。它的收放**跟两侧栏一个规矩**：对话框顶边正中有一条小横条，
  点一下整块收起来（只剩那条小横条、落到视口底边）、再点一下展开，F8 是同一个开关。
  **故意没有"关掉"键**——小横条永远留在视口边上，所以它不会被关到"再也找不到"
- 默认接 **DeepSeek** 的 OpenAI 兼容端点（`https://api.deepseek.com/v1/chat/completions`，
  模型 `deepseek-flash`）；接口地址 / 模型名 / API Key 都在对话框的「设置」里改，**两份都写**（见下面「API Key 不会丢」那条）
- 默认模型选 `deepseek-flash` 是因为**它本身就能看图**（官方定价表：Vision ✓，而 `deepseek-v4-pro` 是 ✗），
  所以文本和「看画面」一个 Key、一个端点就够用，不用配第二套。存量配置里如果还留着 `deepseek-chat` /
  `deepseek-reasoner` 这种已经不在官方定价表里的老名字，读配置时会自动挪到 `deepseek-flash`
- **浏览器直连，不需要本地代理**：DeepSeek 会回显 `Origin`（`file://` 下的 `null` 也回显），
  预检放行 `content-type` + `authorization`；实测拿一个假 Key 能拿到结构正确的 401，
  说明请求真的到了服务端、不是被 CORS 或网络挡在本地
- 它能做的不只是聊天：内置 **126 个工具**（放神经元、批量铺设 / 连接、改参数与权重、模拟激活、
  打包权重块、切相机、编译……），AI 直接调这些工具改你的图；工具没覆盖的还有 `run_api` 兜底，
  可以按名字调 `window.NF` 上的**任意**接口
- **每次调用都是一步撤销**：会改数据的工具执行前自动打一次快照，后悔了 Ctrl+Z 就整体回去
- 危险操作（删选中、生成大图、铺几万神经元、新建 / 打开工程）先弹确认框——
  **这个框是软件自己画的**（`#nfask`，Esc = 取消 / Enter = 确定 / 点框外 = 取消）。
  把「自动执行」关掉后 AI 只会把命令列出来，不碰你的图
- 两条下发通道都支持：端点认 `tools` 就走原生 function calling；不认就自动退回
  「回复里写 json 命令块」，4xx 时自动降级，不用手工切
- 桌面壳的 CSP 放开了 `connect-src`：任意 `https:` 端点 + 本机 `http://127.0.0.1:*` / `http://localhost:*`
  （本地跑的 Ollama / LM Studio 之类也接得上）。以前只放行了 `api.deepseek.com`，填别的地址会被壳子
  挡在本地、报一个跟接口无关的错——这个坑是这轮实测撞到才发现的


**本地大模型：不填 Key、不出网地跑（Ollama / LM Studio / llama.cpp / vLLM）**
- 这些服务都给 OpenAI 兼容端点，所以**没有另做一套协议**：在「设置」里把「接口地址」指向本机服务就行，
  Key 留空。「设置」面板顶上一块专门伺候这件事：
  · **预设下拉 + 「填地址」**：Ollama 11434 / LM Studio 1234 / llama.cpp 的 llama-server 8080 /
    vLLM 8000 / Xinference 9997 / KoboldCpp 5001 / text-generation-webui 5000——不用自己记端口
  · **「探测本机」**：并发扫这七个端口的 `GET /v1/models`，谁答话算谁，顺便把它挂着的模型列出来。
    服务开着但没带跨域头（Ollama 默认就这样）时，它会自己再从软件内部通道问一遍——**照样探得到**（r56 修的）
  · **「刷新模型列表」**：`GET <根>/models`，结果进设置顶部「选择模型」下拉框，挑一个就换上；刷新时保留当前模型，也可手填模型 ID。只填
    `http://127.0.0.1:11434` 这种根地址也行（它自己会再试一次 `/v1/models`）；「接口地址」那一栏
    手打本地地址时也会当场补全成完整路径（公网地址一个字都不动）
  · **「测试连接」**：真的发一句话过去，回报「多久回来 / 模型回了什么 / 认不认 `tools` 参数」
- **「测试连接」不是只看通不通**：最后那一项才是本地模型最常踩的坑——认了不主动调的、直接回 400 的都有。
  不认就把「工具调用」改成「文字命令」
- **「本机」怎么判**：`localhost` / `127.x` / `10.x` / `192.168.x` / `172.16-31.x` / `*.local` /
  `host.docker.internal`（**装在局域网另一台机器上也算**）。判成本地有两个效果：**不用填 Key**
  （这些服务本来就不校验 Key），以及**提示词自动走瘦身版**。公网地址一律仍然要求 Key
- **瘦身模式——小上下文模型能不能用，全看这个**：完整提示词是手册 4.2 万字 + 工具表 2.2 万字，
  约 **4 万 token**；8K / 32K 的本地模型根本装不下，硬塞进去它还会乱调工具。瘦身模式只发
  **7 件套 + 手册大纲**（约 1 千字），其余现查：`list_tools` 列全部 → `tool_help` 看参数 →
  `run_tool` 代调它 → `get_manual(section=…)` 取手册里某一节的原文。**能力一点不少，只多一跳。**
  实测（自测里就有这条断言）：**瘦身 5,667 字符 vs 完整 71,331 字符**（差 12.6 倍）。开关在「设置 → 手册与工具」，
  默认「自动」（接口是本机就开），也能手动定死成「瘦身 / 完整」
- **工具调用方式**：`native`（走 `tools` 参数）/ `text`（不发 `tools`，让模型把命令写在回复里的
  json 代码块 `{"tool":"名字","args":{…}}` 里）/ `auto`（默认：先按 native 发，端点 4xx 顶回来就
  自动退回 text，并在对话里说明白）。小模型多半需要 `text`，设置里能直接定死
- **跨域（CORS）那条命，桌面版给它修了**：页面里的 `fetch` 要过同源策略，而 Ollama / LM Studio /
  llama.cpp 默认不带跨域头——服务明明是好的，页面只会报「连不上」。桌面版为此加了一条 **Rust 侧转发**
  （`nf_ai_http`，走系统自带 curl，不新增 TLS 依赖）：直连失败时自动改从壳子发出去。
  **只替回环 / 内网地址转发**——公网地址不给这条通道，免得它变成任意 POST 的出口。
  **`GET` / `POST` 都发得出去**（拉模型列表就是 `GET`；早先一律按 `POST` 发，
  服务那边只会回 404，看着像「服务没开」——也是 r56 修的）
  代价是这条路**发不出流式**，回答会一次性出现（对话里留一行说明）。浏览器版没有这条路，
  得让服务自己开跨域（Ollama：设环境变量 `OLLAMA_ORIGINS=*` 再重启；LM Studio：Developer 页打开 CORS）
- 采样参数也能调：**温度**、**最大输出**（`0` = 内置默认：非流式 3000 / 流式 4000）。本地模型显存小就压到 512–2048
- AI 标题栏多了一个 **「本地 xxx / 云端 xxx」小标签**，一眼看出当前请求到底出不出网
- **换了接口，系统提示词当场跟着换**（r56 修的漏洞）：这份提示词原本是开对话那一刻定死的——
  从云端中途切到本机，8K 的小模型仍会收到 6.7 万字符的完整版，装不下就会乱答。
  现在改完「接口地址」的那一瞬间就换成对应那一版（自测里有专门一条断言量它）
- **每轮开口前先补一条「最新状态」**（r56）：系统提示词里那份状态是开对话那一刻拍的，干了几十轮早就过期了。
  现在每说一句话前都会贴一条紧凑 JSON（神经元 / 连接 / 选中 / 相机 / 接口数 /模拟激活 …）在用户那句话前面：
  对本地小模型省下一次 `get_state` 往返；对云端则因为开头那几万字前缀一个字不动，前缀缓存还能命中
- **AI 自己也能换接口**：`ai_endpoint` 工具（`base` 填预设 id 或 URL、`model` 填模型名、
  `probe=true` 先扫一圈本机）。用户说「用我本机的模型」时，AI 不用再指导你去点设置面板
**API Key 不会丢：三层保险（这一条是用户点名要的）**

> 起因：上一轮**自测脚本**（还有一轮探针）在验证「能清掉 Key 的时候」真把用户的 Key 抹掉过一次，
> 用户不得不去后台重新申请复制一遍。这一轮把「Key 不许丢」当成一条硬需求来做，并且从
> WebView2 的 Local Storage 里把那次丢掉的 Key 挖了回来、原样放回去了。

- **写两份**：`localStorage`（快路径）+ `%APPDATA%\NeuroForge\settings.json`（明文 JSON，
  覆盖安装 / 换版本 / 重启都还在，可以直接复制备份）。只要这份配置里有 Key，就再留一份
  `settings.bak.json` 当备份。
- **开机并成一份**：四份来源（本机存储、本机备份那一格、`settings.json`、`settings.bak.json`）
  按时间戳取新的那份当底子，然后**拿任何一份里非空的 Key / 视觉 Key 把它补齐**。
- **一条硬规矩：非空的 Key 永远盖不掉非空的 Key。** 页面侧（`aiSaveCfg(force)`）和壳子侧
  （`nf_cfg_write(text, force)`）各实现一遍：
  - `force=false`（自动路径：开机同步、界面顺手一改、脚本）= 进来的 Key 是空的就从磁盘/备份补回去；
  - `force=true`（用户在设置里按「保存」、或按「清掉 API Key」）= 以进来的为准，空就是真的要清空，
    而且**连备份一起清**——否则下次自动写又把它捡回来，用户会以为删不掉。
- **边打边存**：Key 输入框以前只在失焦（`change`）时才写盘，打完直接关窗口就白输一遍；
  现在 `input` 停下 400ms 就写一次，`pagehide` / `beforeunload` 前再冲一次。
- **面板上自己说清楚**：「API Key」下面那行实时显示「已存 N 位 / 备份在不在 / 存在哪个文件」，
  还有一颗明确的「清掉 API Key」（走软件自己画的确认框）。
- **验过的证据**：自测第 19 组专门造了一个坏现场（把现役配置写成空 Key，只剩备份里有），
  验证「自动保存必须把 Key 捡回来」；整段自测**开场快照、收尾原样放回**，所以自测跑在用户机器上
  也不会留副作用。桌面壳里实测：整套自测跑完之后 `settings.json` 里的 Key 还是 35 位。

**自定义工具：AI（和你自己）都能给这个软件加本事**

- 工具表是编译进 exe 的，跑起来的软件改不了自己。但桌面版留了一个**能被重新加载的目录**：
  `%APPDATA%\NeuroForge\tools\*.js`。往里丢一个文件、调 `reload_tools`，新工具立刻进工具表。
- 文件里调 `NF.defineTool({name, desc, args, run})`。校验故意从严：名字要小写字母开头、
  3–41 字符、只能 `a-z0-9_`；不能跟内置工具重名；`desc` 必填；`run` 必须是函数——不合规明确拒绝。
- 给工具作者的桥 `NF.ext`：`tools() / state() / call(名字, 参数数组) / cfgDir() / toolsFile() /
  toolsDir() / manual() / reload()`。
- 加载机制：CSP 有 sha256 白名单、没给 `unsafe-eval`，所以走 `blob:` 脚本注入——**这是实测出来的
  唯一能真跑起来的路**（`addScriptTag` 会被 CSP 挡掉）。
- 边界，如实说：新工具能碰到的还是 `window.NF` 那一套 + `NF.ext`，**不会因此跑到软件外面去**；
  要动软件外面的东西得用 `sys_*`（还要用户开「读写文件 / 运行命令」那两道门）。
  也就是说：**AI 改不了 exe 里编译进去的那张工具表，但可以在 tools 目录里不断添新工具**，
  这就是它「给自己长本事」的正路。

**操作手册（AI 的"从左手册"）**
- 手册正文在 `src/ai_manual.js`，和代码同一个仓库、随版本一起改；`AI_MANUAL_VERSION` 是版本号（当前 `r59`）
- 每次开新对话，发给 AI 的系统提示词 = 手册 + 工具表 + **现场扫出来的接口清单** + 当前状态
  （神经元数、相机、选中、接口数、LOD 档位……）+ 你写在「附加要求」里的那段话
- **接口清单是开对话时从活的 `NF` 对象上现扫的**，所以新加了脚本接口 AI 立刻就知道，手册不会过期
- 菜单命令则是**对账**的：加了菜单忘了写手册，自测会直接报错
  （`NF.aiAudit()` 拿界面里真实的 `data-cmd` 列表去比 `AI_MENU_COMMANDS`）
- 打开工程（含流式、分块载入）时，**文件里带着对话就接着用那一段**；老工程没有这一段、自动开一段新的。
  新建工程 = 一段干净的新对话，上一个工程的几段不会跟过来（见下面「对话存档」）

**对话存档：一个工程里可以有好几段对话**（AI 框标题栏的「对话」）
- 对话不是只活在内存里：**存工程时会跟工程一起写进 `.nforge`**——文件头多一个可选的 `ai` 键，
  记着文件尾那一段对话分区的位置和长度（`{off,len,raw,codec,count,msgs}`，可 deflate 压缩）。
  老软件读不懂这个键会直接忽略，末尾多出来的字节也不影响它读前面的块；布局版本 `version` 一个数字都没动。
  所以同一份工程拷到别的电脑上打开，原来的对话还在，可以接着原来的话往下改
- 一个工程里能攒好几段：标题取第一句用户消息，面板上带时间、条数、最后一句；能打开（整段换上下文）、
  改名、删除（正在用的那段不给删，会明说要先切走），也能随时另起一段。切走的旧对话一直在列表里
- **本机还有一份兜底副本**（IndexedDB 的 `ai` 仓，按工程自己的随机记号 `pid` 归类，静默 5 秒写一次、
  换工程之前会先冲一次）：没存盘就换了工程也能在面板下面「本机存着的别的工程」里把它拿回来。
  它不是仓库——一个工程只留一份、最多留 30 个工程，删了不影响工程文件里的那份
- 存盘时一段对话最多留 160 条上下文、一个工程最多留 40 段（超了先扔最老的，正在用的永远留着）；
  截图（base64）**不写进文件**（一张图比整段对话还大），载入时那一条会写明「这里的画面截图没有一起存」
- 读回来的历史**不带** system 那一条：手册和工具清单是每轮现生成的。旧版本开的对话切回来时会补一条
  「现在的状态 + 以新手册为准」，不让它拿旧记忆当准。载入前一律过一遍 `aiMsgsSanitize`
  （自动保存可能在一轮工具调用中途落盘，那种上下文直接喂给接口就是 400）
- AI 自己也能管这事儿：`ai_sessions` / `ai_session_new` / `ai_session_switch`（**这一轮跑完才真的切**，
  跑到一半换上下文会把 tool_calls 拆散）/ `ai_session_read`（读某一段的内容）
- 数据库从 v1 升到 v2 只为多开一个 `ai` 仓，**升级时只加不减**：已有的 `autosave` 数据一个字节都不动
- 自动生成的提示行里如果带着旧版本写坏的时间（时间戳 32 位溢出，印成 1969 年），载入时按年份清掉；
  人和 AI 说的话一个字不动（`aiLogClean`：老工程文件、老存档、老 JSON 三条路都过它）

**AI 看画面：能做到什么、做不到什么**

编辑器能截当前视口（`NF.shot()`），也能把它作为一条带图的消息发给模型。

**接口只有一套**：主接口那组（API Key / 接口地址 / 模型）。DeepSeek 官方的 `deepseek-flash`
本身就收图（同一套 OpenAI 兼容端点、同一个 Key），所以**一个 Key 就能看画面**，不需要另配视觉端点；
`deepseek-v4-pro` 不收图，填它看画面会被 400 顶回来。设置里那组「视觉接口 / 视觉模型 / 视觉 Key」
是**可选的覆盖**，留给"主接口是纯文本、另有别的多模态端点"的用户，留空就用主接口。

软件不替接口下结论：带图的请求被 4xx 拒了，会自动把图摘掉、按纯文字重发一次，并把接口的原话贴在对话里。
没填 Key 时，「看画面」按钮和 `see_screen` 工具都会明确说"发不出去"，不会假装看过了。
带图的消息只能放在 user 消息里（system / assistant 里带图会被接口拒）。
截图走 JPEG 0.9——同样内容 PNG 要 600 KB，JPEG 只要四分之一。


**AI 的外部操作：桌面版专属，默认关，两道门**

浏览器版只能动编辑器里的东西。桌面版可以给内置 AI 开一条**外部操作**通道，让它装软件、下模型、跑脚本：

- AI 面板「设置」里有两个勾选框：**允许 AI 操作本机（按路径读写文件 / 从网上下东西）** 和
  **允许 AI 在本机运行命令（高风险）**。默认都关着，而且**故意不写进 localStorage** ——
  每次打开软件都要重新勾一次；关掉立刻生效（门在 Rust 侧，不在这层脚本里，脚本接口硬开也绕不过去）
- 门开着时 AI 手里的工具：`sys_info`（不设门，随时能探环境）、`sys_list_dir` / `sys_read_text` /
  `sys_write_text` / `sys_download` / `sys_open_project`（走「读写文件」门）、`sys_run`（走「运行命令」门）
- `sys_info` 报出 PATH 上 python / py / pip / node / npm / git / curl 的绝对路径；探到的 python 落在
  `WindowsApps` 里时会多带一条 `warn` —— 那多半是 Microsoft Store 的占位程序，跑不出东西，该试 `py`
- **没有网页搜索工具，但有完整的联网能力** —— 这一条最容易搞错：
  - 内置 AI **看不到**百度 / Google / Bing 的结果页，也不能点网页、不能翻页；
  - 但 `sys_download`（curl）和 `sys_run`（任意命令）是真通的，所以「按名字找东西」照样办得到：
    去问每个仓库 / 包管理器**自己的搜索接口**，它们全都是普通 HTTP，curl 一句就能拿 JSON。
  - 本机实测（真跑过）：`sys_download` 从 GitHub 拉下 `mnist-1.onnx`，**27,266 字节 / 3.7 秒**，
    `sys_stat` 复查字节数一致；`curl "https://huggingface.co/api/models?search=mnist"` 直接拿回 JSON；
    本机 `winget 1.29.290` / `Python 3.13.7` / `pip 25.2` / `git 2.53.0` 都在（`python` 本身指向
    `WindowsApps` 占位程序，要用 `py -3`）。
  - 四个常用搜索接口：`https://pypi.org/pypi/<包名>/json`（找包）、
    `https://huggingface.co/api/models?search=<关键字>`（找模型）、
    `https://api.github.com/search/repositories?q=<关键字>`（找仓库）、`winget search <关键字>`（找软件）。
  - **一个坑**：`raw.githubusercontent.com` 上的大模型文件常只回一份一百多字节的 **LFS 指针文本**
    （正文是 `version https://git-lfs...`）。要拿真文件得走
    `https://github.com/<owner>/<repo>/raw/<分支>/<路径>`。
- **诚实边界**（这一段是重点）：
  - **这不是沙箱**。Rust 侧只拦「明着来的」破坏性写法（`diskpart` / `bcdedit` / `mkfs` / `format c:` /
    `shutdown /` / `del /s /q` / `rd /s /q` / `rm -rf /` / `reg delete` / `sc delete` / `net user` /
    `-EncodedCommand` 等），命中直接拒并告诉你命中了哪一条。真要防住恶意命令，
    靠的是别在装着敏感东西的机器上开这个开关
  - 跑命令：stdin 接空、默认 60 秒超时（最多 600 秒）、**超时连子进程树一起杀**（只杀 `cmd` 不够，
    孙进程还攥着输出管道；顺序也得是先 `taskkill /T` 再 `kill`，反了就找不到树）、每条流最多回 200 KB
  - **中文不乱码是靠「写临时 .cmd」做到的**：`cmd.exe` 会把命令行字符串按控制台 OEM 代码页转一遍，
    直接 `cmd /C "echo 中文"` 回来是乱码；改成把命令写进一个临时 `.cmd`、文件头一行 `chcp 65001`，
    cmd 就按 UTF-8 读后面的内容。实测 `echo 中文OK` → `中文OK`
  - 读文件：`sys_read_text` 默认 256 KB、一次最多 1 MB，接着读要传 `offset`；按路径打开工程一次最多 512 MB，
    再大得走「文件 → 分块载入 / 流式载入」；写文件一个最多 64 MB；下载走系统自带的 `curl.exe`
  - 只有当前这个会话有效：软件重启，两道门自动回到关
- 会顶掉整张图的操作（`sys_open_project`）跟「打开工程」一样先弹确认框

这一条也在桌面壳里真跑过：把应用装好、用 CDP 连进去（`_dump/_deskprobe.mjs`），40 项断言全过 —— 门关着三种操作全被拒、
开门后列目录 / 读写文本（含中文）/ curl 下载 / 404 如实报错 / 超时被杀 / 黑名单拦截 /
`cwd` 与 `timeout` 参数生效 / 按路径打开 `.nforge` 与 JSON 工程、关掉开关立刻又拒。

**AI 智能体：不是一次问答，是一直做到你说停**

这一层是照着「外部那些麻烦事直接丢给软件里的 AI」做的——长活、找文件、改一处、流式、随时叫停。

- 一轮提问里它会连着调很多次工具，每调一次看一次结果再决定下一步；上限默认 **80 轮**
  （「设置 → 最多来回」可改 4–400）。到上限它会停手并说一句，你再发「继续」就接着跑——那不是失败。
- **长活一律丢后台**：`job_start` 立刻拿回一个 id，`job_poll` 看增量输出（带 `cursor` 不重复读、
  可以 `wait` 最多 30 秒等有输出再返回），`job_kill` 连子进程树一起杀。`pip install` / `git clone` /
  跑训练 / 起仿真服务 / 编译大项目都走这条，不会把对话卡死。同时最多 8 个，每个最多留 2 MB 输出。
- **找东西用 `sys_find`**（`name` / `path` / `text` 三种模式，单次最多扫 4 万个文件，回「路径:行号:那一行」）；
  **改文件里的一处用 `sys_edit_text`**：`find` 必须一字不差、而且在文件里唯一，不唯一就报错让它多带两行上下文
  ——宁可报错也不把文件改坏。另外配了 `sys_stat` / `sys_mkdir`。整篇重写（`sys_write_text`）留给「写新文件」。
- **流式输出**：勾上以后边写边显示（思考过程一起显示）。走 SSE，`tool_calls` 在流里是按 index 拼起来的；
  端点不认 `stream` 就自动关掉流式、把这一步原样重来一次，不算你一次失败。
- **思考强度可选**：AI 标题栏上就有一个常驻的「思考」下拉框（不用展开「设置」），设置面板里也有一档
   （跟随接口默认 / 关 / 低 / 中 / 高 / 最高），两处是同一个值、改哪边都同步；AI 自己也有一条
  `ai_think` 工具，你直接跟它说「把思考强度调到 high」就行。走的是 DeepSeek 那套 `thinking` +
  `reasoning_effort`；端点不认这两个字段时会摘掉重发一次并如实说明，而且**只在确实是这两个字段的
  问题时**才这么判——其它 4xx（比如消息数组不合法）不会被赖到思考参数头上。
- **服务端忙会自己重发**：接口回 429 / 500 / 502 / 503 / 504（限流、排队、Service is too busy）时，
   不再把整轮对话当场掐掉，而是退避 1.2s / 3s / 6s 各重发一次（最多 3 次），每次在对话里留一行说清在等什么；
   重发用的是**完全相同的请求体**（思考强度那套字段不会被悄悄摘掉）。实测（本地桩返回 503×3）：
   4 次请求、3 行提示、最后一句正常回答。
- **随时能停**：标题栏那个「■ 停止」只在跑的时候出现，按下会 `AbortController.abort()` 掐断正在下的那一段
  （实测 61 ms 内停住），日志里如实写「你按停了」。**它只让 AI 停手，不会掐掉已经起来的后台任务**——
  要停那些得让 AI 调 `job_kill`，或者自己去关那个窗口。
- **会话长了会自动压缩**：前面的原始对话被压掉，换成一张「做过什么」的单子（调过的工具 + 结果摘要），
  并明确告诉它「不要重做」。同一条路连着走三遍、或者连着失败三遍，会塞一句「别原地打转」让它换做法。
- 标题栏那个小标（`本机：关 / 只读写 / 全开`）随时告诉你 AI 现在碰不碰得到这台机器；边上还有「后台 N」，是还在跑的任务数。
- 一个实测撞到的坑，已经写进工具说明和手册：**命令输出走管道，很多程序会攒够一块才吐**
  （`echo` 这种小输出可能要等命令整个跑完才看得见）。看不到新东西不等于卡住了——`job_poll` 会给 `running` 和总字节数。

这一层在装好的桌面程序里真跑过：`_dump/_deskprobe.mjs` 连上壳子跑 **40 项断言**——增量输出与 cursor、
杀任务、标题栏后台数、`sys_find` 三种模式、`sys_stat` / `sys_mkdir` / `sys_edit_text`（唯一 / 不唯一 / 找不到三种结局）、
流式文本、流式里的工具调用、按停止掐断（后面那段确实没再来）、端点不认流式自动退回、收尾把门关回去。
配套的假端点 `_dump/_stubai.mjs` 就是为这个写的（`/nostream/` 前缀模拟「不认 stream」的端点）。

**接口运行时：外界信号真的进得来、真的出得去**

「接口」菜单分两页：**标记**（谁接收外界信号、谁输出到外界，编译时就是模型的输入 / 输出张量）和
**运行时**（真的接上信号）。打开运行时总开关以后整条链子是自动的：
**输入接口收值 → 按阈值往前传 → 输出接口一激活就触发它绑的动作**。
- 输入接线四选一：不接线 / 键盘按键 / 常值（一直保持）/ 定时脉冲
- 输出动作五选一：提示 + 日志 / 软件内按键（合成一个真的 `KeyboardEvent`）/ 系统按键 /
  HTTP POST / 运行脚本
- 绑定的按键会被**接管**（勾上「接管已绑定的按键」，那个键只喂信号、不再触发软件快捷键——
  `stopImmediatePropagation`，同一个节点上的快捷键也拦得住）
- 键盘输入**只在前台窗口收得到**——操作系统定的，任何软件都改不了；想从别的程序送信号进来，
  用下面的信号通道，或者直接调 `NF.ifaceFeed(编号, 值)`
- 「系统按键」注入到当前前台窗口，只有桌面版能做；软件自己是前台时等于打回自己，这一点面板上写明了

**通用信号通道：对接别的软件 / 设备（Simulink / LabVIEW / Python / 硬件都行）**

这一层刻意做成跟「对面是谁」无关：**传输方式 × 编码 × 信号位**，三段都能换。

| 段 | 可选 |
| --- | --- |
| 传输（收） | UDP 监听 / TCP 服务端 / TCP 客户端 / 串口 / HTTP 轮询 / WebSocket |
| 传输（发） | 上面全部，再加「只写日志」 |
| 编码 | JSON / 文本（空格分隔）/ CSV / float32 小端二进制 / int16 小端二进制（按 1/32767 归一化）/ 自定义脚本 |
| 信号位 | `12, 13*2, 20*0.5+0.1`（编号 / 编号×增益+偏移，按顺序对应消息里的第 1、2、3… 个数）；整帧也可以全写成「编号=值」，那就按编号点名，与顺序无关 |

- 收通道收到一帧 = 按信号位写值 → 照常按阈值往前传
- 发通道 `周期 > 0` 就按周期发；`周期 = 0` 只在信号位**出现上升沿**时发一帧（掉下去再上来算新的一次，
  一直是正的不会重复发）
- 值不是「神经元动作」发出去的，是通道从最近一次前向结果里按信号位取——所以「数据出」不必给神经元额外接线
- 例子（收）：对面 Python 里 `sock.sendto(b"1 0 0.5\n", ("127.0.0.1", 9000))`，
  软件这边建一条「UDP 监听 + 文本 + 信号位 `0, 1, 2`」的收通道；要传二进制就选 `float32 小端`，
  对面 `struct.pack("<3f", …)` 发过来
- 例子（发）：建一条「UDP 发送 + 文本 + 信号位 `7, 8` + 周期 20 ms」的输出通道，填上对面的地址和端口
- 诚实边界：**UDP / TCP / 串口只有桌面版**（走 Rust 侧的 `nf_io_open / nf_io_send / nf_io_poll`），
  浏览器版会明说打不开，不会假装能用；HTTP / WebSocket 两边都能用。通道配置（传输 / 编码 / 信号位 / 周期）
  随工程文件存下来，但「打开着」这件事不会——新会话里要重新打开一次

**接物理仿真：MuJoCo 闭环（含宇树 Go2 四足）**

一条命令把「观测进、控制出」接好：`wire_mujoco`（工具 / `NF.wireMujoco`）认出观测区与输出细胞，
标成输入 / 输出，建好两条 UDP 通道（默认观测 9101、控制 9102），并返回对面该敲的命令行。
对面用仓库里的 `tools/bridge_mujoco.py`（通用桥，不认特定场景）：

```
py tools/bridge_mujoco.py --xml 模型.xml --body auto --obs pro --proprio-cells 480 --obs-port 9101 --act-port 9102 --fold 10
```

- `--body auto` 按模型自己认身体：`humanoid`（小人，10 个电机，控制量 [-1,1]）或 `go2`
  （四足，12 块肌肉：收到的数按 `--fold` 折成**发力 0~1** → 目标角 → PD 力矩）。
  Go2 模型不在本机时加 `--allow-download` 会自己去 MuJoCo Menagerie 下全套。
- **三个口径别搞混**（返回里分别给了）：`dimsOnWire` = 每帧真发出去的浮点个数（= 输出细胞数，
  出通道是「一个信号位一个值」、不折叠）；`groups` = 桥按 `--fold` 压完的路数；`executors` =
  身体真正有几个执行器（要传 `actCount` 才知道）。born-wired-cortex 的运动区 160 =
  腿 12×10 + 眼球 4×10，接 Go2（12 个执行器）时多出来的 4 组眼球肌桥会丢掉 —— 那是身体没有眼球，
  不是接线错；桥启动时会打一行口径说明把这件事写清楚。
- **实测（本机，整模型 + Go2）**：不驱动运动皮层时躯干停在 **0.18**；把 12 块肌肉各前 5 个细胞
  喂 1（= 5 档 = 发力 0.5 = 站姿）后躯干升到 **0.26** 并稳住；撤掉这批值又掉回 **0.18**。
  同一轮入通道 `rx` / 出通道 `tx` 都在涨，桥报「收到控制 1111 帧」。
- **出通道任何情况下都不会发 NaN**：喂值接口不收非有限值（按「撤回」处理并记 `bad` 计数）、
  前向收集种子时再筛一遍、发送前兜底成 0。这条是实测踩出来的 —— 以前一个非数字值会挂成 NaN、
  顺着连接传遍全网、最后从出通道发给外部仿真，对面的控制器当场就是 NaN。桥那侧也挡一层，
  并且物理真发散（qpos/qvel 出 NaN）时自动复位、结束时报出复位次数。
- **诚实边界**：低密度的本体感觉码点不亮下游是**模型本身的性质**（皮层随机兴奋权重上限 0.15、
  放电阈值 1.0，一个下游细胞要凑够十几个同时亮的输入才过阈），不是接线错。要「整片亮」就点全区
  细胞，要复现反射就把真实姿态编出来的码喂进去 —— 别为了让机器人动起来去编结果。

## 实测性能

在本机（RTX 3070 Ti / 浏览器 WebGL）实测：

| 规模 | 生成耗时 | 场景重建 | 单帧绘制 | 选中并高亮出入边 | 连线拾取 |
| --- | --- | --- | --- | --- | --- |
| 22 神经元 / 94 连接（示例网络） | — | 0.6 ms | 0.70 ms | < 1 ms | 0.10 ms |
| 10,000 神经元 / 39,842 连接 | 27 ms | 16 ms | **0.20 ~ 0.50 ms** | 17 ms | 0.23 ms |
| 30,000 神经元 / 238,053 连接 | 122 ms | 62 ms | 0.20 ms | 3.1 ms | — |

关键点：**空闲时完全不渲染**（不交互时 GPU 占用为 0），交互时只上传改动的那一个实例。
选中神经元时高亮只重绘**它的关联边**（不扫全图），所以耗时取决于该神经元的度数，与图规模无关。

三处自动降级保护，避免大图下鼠标发涩：
- 连接数 > 12 万：不再做悬停高亮
- 连线数 > 40 万：模拟激活提示规模过大并拒绝执行
- 节点或连接数 > 15 万：选中时不再淡化其他对象（此时多余的色彩区分反而看不清）

上表最后一行就是降级生效后的结果：23.8 万连接下选中耗时 3.1 ms，比 4 万连接时还快。

框选也一样：拖一个框选一片走的是**一次 O(连接数) 的屏幕空间扫描**，不是每条连线单独判。
12 万神经元 / 60 万连接下，从 60 万条里扫一遍并选中命中的 1.2 万 / 3.5 万条，
连同批量标脏一共 **9 ~ 16 ms**（这条数字 `_perf.html` 每次都会打出来）。
命中上万条时走批量上传区间，不会退化成几万次零碎上传；两端都在框外、横穿过去的长连接也照样框得到。

### 千万条边上的拾取：只搜「画面上真的画出来的」那一批

16.8M 条连接的图全铺在屏幕上时，「跟光标附近相交的块」几乎是**全部**：按块 + 预算的拾取要么
扫一百多毫秒、要么（以前）干脆返回 −1 —— **实测在这个视角下连最强的那几条线也 10/10 次点不中**，
「屏幕上看得见、鼠标点不着」。现在的做法是两层：

- **权重阈值开着**（默认，见左栏「只显示强连接」）→ 建一张**可见边索引**（画面上真的画出来的边号，
  本机实测 16.8M 条 → **278,022** 条）。拾取就在这张表里找，**全搜一遍 2.3 ms**，不会漏掉表尾的边
  （以前只敢搜前 200 万条，落在后面的线永远点不到）。索引 O(边数) 建一次、只在阈值 / 权重 / 拓扑变了以后重建。
- **阈值关掉（全部显示）** → 退回「按块 + 预算」：一次点选最多 200 万条（**~12 ms**）、悬停 30 万条
  （**~1.6 ms**），没扫完就把已经找到的最近一条返回去，并在状态栏提示「把镜头拉近再选」。

悬停 / 框选都只认**画面上看得见的线**：阈值挡掉的线既画不出来、也选不中（框选里那一句
`edgeHiddenByW` 顺带让 16.8M 条的框选从「扫全表」变成几十毫秒，本机实测 220×180 px 的框 89 ms）。
量开销用 `NF.pickBench(预算, 次数)`，看 `NF.bigProbe().pick` 里的 `vIdx` / `trunc` 就知道索引建没建、上次拾取有没有被截断。

`prototype/_perf.html` 是可复跑的基准页（`make_perf_check.mjs` 生成），规模自选：
`_perf.html?n=500000&l=200&f=6`。

### 分块渲染 + 逐块视锥剔除：拉近看局部不掉帧

「整张图一个 `InstancedMesh`」有个绕不过去的坎：一次 draw call 就是全画。
几百万个顶点里哪怕只有一个落在屏幕里，GPU 也得把整份提交一遍——剔除根本无从谈起。
现在渲染层按块拆开了：

- **一份缓冲，多块共享**：`InstancedInterleavedBuffer` 配带偏移的 `InterleavedBufferAttribute`，
  每个块指向**同一份 CPU 缓冲**的不同区间。拆块不复制任何实例数据：
  12 万神经元 / 60 万连接下是 4 + 19 + 19 = 42 个块，显存里还是那三份缓冲。
- **块宽自适应**：1024 起步、65536 封顶，按规模挑一个让块数落在 32 左右的值。
  所以 **GPU 对象数跟模型规模脱钩**：12 万时每块 32768，120 万时仍是 32 块。
- **包围盒只增不减**：写实例时顺手把那一块的盒子撑大，盒子一旦算过就只会变大。
  剔除因此永远保守——宁可多画一块，绝不误剔。
- **每帧只跑「块数」次求交**（几十次），与图规模无关。
- **细线层**同样是每块一个 `LineSegments`，共用同一份顶点 / 颜色缓冲，靠各自的 `drawRange` 选自己那一段。

验收标准只有一条：**同一视角下开 / 关剔除必须逐像素一致**。
`prototype/_chunkcheck.html`（`make_chunkcheck.mjs` 生成）就是这么对的账——
`NF.grabFrame()` 把整屏像素读回来，`NF.pixelDiff()` 逐点比，差异必须为 0；
同时逐块对账「这块画的实例数 == 它负责的下标区间」「包围盒真的框住了自己的成员」。

| 实测（12 万神经元 / 59.9 万连接，RTX 3070 Ti / Chrome） | 结果 |
| --- | --- |
| 块划分 | 神经元 4 块 / 圆柱 19 块 / 细线 19 块，块宽 32768 |
| 每块画的实例数 == 它那一段 | 0 处不符 |
| 包围盒框住自己的成员（连线算两端） | 0 块越界 |
| 近看时被剔掉的块里，有没有落在视口里的神经元 | 漏 0 |
| 近看 / 远看：开剔除 vs 关剔除 | **差异像素 0 / 0** |
| 近看每帧提交耗时（同视角，开/关交替 6 轮 × 各 30 帧，各取最小） | 开剔除 0.03 ~ 0.07 ms vs 关剔除 0.07 ~ 0.15 ms；差值落在测量噪声带内 |

**这些数字的口径要说清**：帧间隔被垂直同步钉在 16.7 ms，量不出差别；
而 Chrome 里 `gl.finish()` 也不代表 GPU 真的干完了。所以这里量到的是
**CPU 每帧提交出去的开销**（剔除省的就是 draw call 提交），不是 GPU 耗时——
本机还没到 GPU 吃亏的规模。

> **一句自我更正**：这一行早先报的是「开剔除 0.04 ms vs 关剔除 0.16 ms，少 75%」，
> 但那个数字不稳定——同一份代码连跑三次会五五开地换边。原因是单边连跑会撞上机器上的漂移
> （别的进程起伏、热降频），而两边的真实差距本来就在几十微秒这个量级。改成开/关交替采样
> 之后，结论变成**量不出稳定差别**。所以这里如实写成「没有可见的额外开销」；
> 剔除到底省了多少块，由上面那条确定的断言（`drawn` 对账）负责，不靠计时。

**诚实边界**：屏幕外的块只是不再提交，**实例数据仍然占着内存**——
剔除省的是每帧的 GPU 提交，不是内存。要省内存是另一件事，见下一章。

顺带修掉一个真 bug：档位名写错一个词（`medium` / `simple`）会静默落进一个谁都不匹配的档位，
三层可见性全判 false——**连线整层消失**，界面上却完全看不出来。
现在档位名统一收口到 `normTier()`，认不出来的落回 `auto` 并 `console.warn`，
自测里也补了这条回归。

### 流式载入：打开只看摘要，靠近才解压

分块渲染解决的是「每帧提交多少」，流式载入解决的是「内存里放多少」。
菜单「文件 → **流式载入…**」走的是另一条路：**打开时只读文件头，一块都不解压**。

- **文件一大就走「文件 → 打开大工程（按路径）」**：这条路按**文件路径**分段读，不是
  `<input type=file>` 那种「先把整份交给浏览器」。104 MB / 1,681 万条边的工程因此也能
  在不整份进内存的前提下打开（实测 22~35 ms）。用户亲手在原生对话框里选过的路径会进白名单，
  **读它不需要开 AI 那道门**——开自己的大工程不该被要求先把机器交给 AI。

- **数据源是文件本身，不是内存里的一整份**。`.nforge` 从 `<input type=file>` 拿到的是个 Blob，
  块用 `file.slice(a, b).arrayBuffer()` 按字节区间读——**整份文件从头到尾不会出现在内存里**。
- **打开 = 只读 `16 + 头长度` 个字节**，然后用索引表把每块的包围盒画成 12 条棱的线框盒。
  于是「这个模型占了多大地方、大致什么形状」是立刻能看见的。
- **解压 = 相机靠近哪块才解哪块**。判据是「这块的包围盒投影到屏幕上有多大」（不是死板的距离），
  在视锥内、投影超过「细节阈值」才解压；每帧最多解一批、最多花 6 ms，结果分帧提交进场景。
- **编号只往后加**：块 k 一载入，它那段神经元就落在 live 数组尾部，`fileId → liveId`
  靠**块级基址**换算（每块一个数，不是每个神经元一个数）。**不驱逐时，已分配的 liveId 一个都不改变**——
  所以选区、撤销、编译、拾取这些代码一行都没为流式载入改过。被驱逐是唯一会重编号的操作，
  它自己负责把所有引用 id 的地方（选区 / 名字 / 权重块 / 挂起的边 / 撤销栈）搬一遍。
- **跨块的边先挂起**：`.nforge` 的边是「按起点」切进块的，所以 src 在本块、dst 在后面的块时，
  这条边先按「dst 所在块」挂着，那块载入时再补上。HUD 与面板都实时显示还挂着多少条。
- **半载入的图不许存**：点「保存工程」会被明确拦下并说明还差几块，免得存下一张残缺的图。
- **权重块按段读**：权重块区在文件里是「一块一段」存的（`codec: "parts"`），每段带自己的包围盒，
  于是挑段时**一个字节都不用解压**——只载入部分神经元块时，跟它们包围盒不相交的段连读都不读。
  左栏「自动载入附近的权重块」开关（默认关）打开后，每批新块进场景时会顺手把相关的段补进来；
  读过的段有账本，反复调用不会重复建块，被驱逐的段会退回「没读过」等再靠近时重读。
- **块本身可以是一片空间**：用「另存为空间分块工程…」存出来的文件，块 = 一小片空间
  （Morton Z 序 + 八叉树，见「空间分块」节）。这时「靠近哪块解压哪块」才真的等于
  「靠近哪片空间解压哪片」。实测随机取一个点，包围盒含它的块数：
  2 万神经元时 **10 → 0.9 块**、6 万时 **30 → 1.0 块**、20 万时 **100 → 1.0 块**
  （线性切块下这个数就等于块数本身，因为每块都横跨整个模型）。
  不这么存也能用，只是块界是神经元编号区间，跟画面对不上。
- **超预算就驱逐，上限优先**：驻留神经元超过上限（可调，默认 20 万）时丢远处的块腾地方。
  丢的顺序是「先丢看不见的、再丢看得见的」，两边都按离相机从远到近；
  **选中的 / 悬停的 / 连线起点所在的块永远不丢**。
  注意「看得见」跟「装得下」是两件事：相机远平面现在跟着视距自适应（见下文「画面全黑」节），
  所以眼前的块完全可能比预算还多 —— 这时候**上限赢**，连看得见的块也照丢
  （驱逐计划里记成 dropVisible），因为上限就是用户拿来防爆内存的。
  于是**在上限之内可以一直往前飞**——不加这一条的话，飞过的地方会把当前容量占满，
  之后相机往哪走都载不进新块了。被丢掉的块只是**回到线框盒**，再靠近会重新解压；端点被搬走的边转成「挂起」，等对端回来时再接上。

实测（样本 `prototype/_streamdemo_raw.nforge` = `py -3 tools/gen_stream_demo.py` 生成，
24 块 / 49,152 神经元 / 139,264 连接 / 24 个权重块 = 24 段）：

| 指标 | 结果 |
| --- | --- |
| 文件大小 | 1,276,639 B（其中权重块区 48,317 B） |
| **打开时读进来的字节** | **7,682 B（0.60%）** = 16 + 7,666 |
| 打开后的 resident / 场景里的神经元数 | 0 块 / 0 个 |
| 打开后画出来的线框盒 | 24 个盒子 / 576 个顶点 |
| 相机对着这条线的中段时被挑中的块 | 13 块（阈值 1px：视锥里按屏幕像素大小挑；相机远平面现在跟着视距自适应，不再写死 6000） |
| 一次自动 tick 之后 | 载入 1 块，累计只读了 60,736 B |
| 只驻留 3 块时读权重块 | 只读 3 段 / **6,048 B**（整段 48,317 B，段均 2,013 B） |
| 点「全部载入」之后 | 读的总字节 **1,276,639 B = 整个文件**，顺带读出 24 个权重块（12,288 个权重） |
| 把上限压到 4 块后驱逐一次 | 丢 20 块 / 腾出 40,960 个神经元，留下的 4 块逐位不变 |
| 相机沿 X 走 15 站（上限还是 4 块） | 峰值驻留 8,192 = 上限，越界 0 次；13 站发生了驱逐 |

**诚实边界**：

- **驱逐省的是「能一直往前走」，不是内存**。数据模型（`nPos` / `eSrc` …）是**预分配**到**当前容量** `MAX_N` / `MAX_E` 的（容量按需增长，
最多到绝对天花板），渲染实例缓冲是从 8192 一路翻倍涨上去的，两者都不会因为驱逐而还给系统。
  驱逐真正解决的是：**在上限之内可以无限漫游**。
  它还会**清空撤销记录**（快照存的是整份数组 + 老编号，驱逐后对不上），
  被丢掉的块的「名字已应用」标记也一并撤掉，下次载回来会重新挂上。
- **预算塞满、而剩下的块全都被选中 / 正在用时，这一帧就是载不进新块**，会弹一次提示。
  这是预算真撞穿了，不是 bug：把上限调大，或者先松开选择。
- **块界默认是「神经元区间」，不是空间**。图里空间上相邻的两个神经元，编号可能隔得很远，
  于是被切进不同块——「靠近才解压」挑出来的那几块，跟画面对不上（本节表格里的样本
  就是这种**默认切法**，它就是最初那份 demo 的样子）。
  解决办法已经做了：**文件 → 另存为空间分块工程…**（`order: "spatial"`，见「空间分块」节），
  存出来的块 = 一小片空间，实测包围盒体积收紧约 65 倍、「看向一处」要解压的块数
  从「整张图」降到个位数。
- **旧文件的权重块区只能整段读**：`codec: "raw" | "deflate"` 的老形式是一整段 blob，
  挑不动——只能等神经元块全都在场时整段读一次（新存的工程一律走 `parts` 形式）。
  段的划分粒度就是**块**：一个权重块再大也是一段，段内没有再切。
- 单块载入的上限仍是**当前容量** `MAX_N` / `MAX_E`（初始 8,192 / 16,384，按需增长，绝对天花板
  16,777,216 / 67,108,864）——流式载入省的是
  「没看到的那部分」，不是把上限抬高了。

顺带修掉一个真 bug：流式打开后「框住整个模型」会被 `OrbitControls.maxDistance`（2600）
把相机拽回来，模型摊得越开越明显（这个工程沿 X 轴铺了 34,500 个单位）。
现在只有这一处（打开流式工程后的初始机位）按模型尺寸放宽上限。

### 大图卡顿：场景重建已经分片化

原来的瓶颈是 **场景重建**：50 万神经元 / 200 万连接时 `rebuildScene()` 一口气做完整场，
主线程冻住约 980 ms。它只在载入 / 批量生成 / 删除这类结构性改动时触发，旋转缩放不受影响，
但"卡一秒"在工业软件里是不能接受的。现在改成三件事：

- **三层分离**：神经元球 / 圆柱连线 / 细线连线各有独立的 `buildMask`。
  远看（简档）时球和圆柱**根本不建**，切到高档才补上；没建的那层既不写也不画。
- **分片推进**：每片 2.4 万个元素，片间看一眼时钟。同步调用方最多先扛 40 ms，
  剩下的交给渲染循环每帧继续建 7 ms。`count` / `drawRange` 跟着推进，
  画面是"逐段长出来"的——这本身就是进度条（HUD 显示百分比）。
- **批量实例上传**：把上万次 `addUpdateRange` 合并成一段，
  否则 200 万条连接光临时对象就要分配几百万个。

| 指标（50 万神经元 / 200 万连接） | 改造前 | 改造后（本机实测） |
| --- | --- | --- |
| 整场三层重建 | 980 ms 一次卡死 | 172 ms 摊到多帧（球 41 / 细线 46 / 圆柱 85） |
| 帧间隔 p50 | — | 16.7 ms（锁在 60 fps 上） |
| **主线程单次最长阻塞（渲染侧）** | 980 ms | **≤ 40 ms**（`BUILD_SYNC_MS` 上限，之后每帧 ≤ 7 ms 接着建） |

顺带修掉两个真 bug：

- 容量翻倍时新建的 `InstancedMesh` **没有重新 `scene.add()`**，
  所以神经元一超过 8192 个画面上就什么都没有（CPU 数据全对，只是没挂进场景图）。
  现在 `debugScene()` 会返回 `inScene` / `visible` 探针，这类错跑一次校验就能抓到。
- 批量生成时 `addEdgeRaw` 每加一条边就查一次扩容，200 万条连接要反复重分配 + 重传 8 次。
  生成器一开始就知道边数上限，先预分配一次即可：50 万规模的生成本身从 441 ms 降到 350 ms。

剩下的最长卡顿（实测 **556 ms**）**已经不在渲染侧**，而是"批量生成 / 载入"这一步同步建图本身
（50 万神经元 + 200 万连接的数组填充、CSR 邻接表重建，以及一次性约 160 MB 的缓冲分配）。
下一次要治的就是它：把生成与解析也切成时间片。
上面的数字由 `prototype/_perf.html?n=500000&l=200&f=6` 产出（结果同时落到 `_dump/perf.txt`），换机器请重跑。

**示例网络是固定种子的**：每次载入的权重都一样，方便对照、复现和比较编译结果。

### 画面全黑、像被什么东西挡住了：雾 + 远裁剪面 + 挡在前面的板子

用户报的现象是「视角移到某些位置以后整屏全黑，什么都没了，稍微换个角度又有画面」。
查下来是**三条写死的参数**，每一条都能让画面一个像素都不剩：

| 写死的东西 | 症状 |
| --- | --- |
| `scene.fog` 定死 `near=320 / far=1400` | 超过 1400 单位的东西 100% 糊成背景色：模型一大、或者镜头一推远，整片被雾吃掉 |
| `camera.far` 定死 `6000` | 镜头走到模型外面，整个模型越过后裁剪面被裁光，屏幕上什么都没有 |
| 清屏色是默认的**纯黑** `(0,0,0)`，而雾色是 `#080b10` | 被雾吃掉的那一片跟真空背景**不是一个颜色**，在画面上就是一块看得见的暗色方块（用户的原话：像被什么东西挡住了） |

现在这几条都改了：

- **雾跟着视距长**：取「注视距离」和「镜头到整图最远那一侧（镜头到图心 + 图半径）」里更大的那个 `need`，
  雾设成 `need × 0.55 → need × 2.2`。远处只是轻微变淡（保留深度线索），永远吃不掉模型。
- **远裁剪面跟着长**：`max(2000, 最远一侧 × 2 + 200, 视距 × 3)`，并且**一定**比「最远的那个神经元」更远。
- **清屏色就是雾色**（`renderer.setClearColor(FOG_COLOR, 1)`）：被雾吃掉的那一片和背景完全同色，
  分不出来，也就不可能再出现「一堵暗墙」。canvas 本来就不透明，视口那层 CSS 径向渐变本来就透不过来，
  所以背景干脆交给它。
- **整图包围盒缓存跟着数据作废**：刚铺完一大片 / 撤销 / 载入之后，雾和裁剪面立刻按**新**包围盒算
  （以前最多滞后 20 个**已绘制**的帧 —— 而空闲时根本不绘制，于是可以滞后很久，表现就是「铺完还是一片黑」）。
- **权重块 / 算子板子贴到镜头前会让开**：板子是永远正对相机的 billboard，走到跟前时它比整个视野还大，
  满屏热力图把神经元全挡住。现在按**屏幕覆盖率**淡出：1 屏以内正常画、1~4 屏淡出、4 屏以上收掉。
  覆盖率是相对量，小图和大模型共用同一套阈值，不用手调参数。

实测（本机 RTX 3070 Ti，无头 Chrome；对照图存在 `_dump/fog-old.png` / `_dump/fog-new.png` / `_dump/plate-old.png` / `_dump/plate-new.png`）：

| 场景 | 老参数 | 现在 |
| --- | --- | --- |
| 48,000 神经元（跨度 1,869）的模型，镜头距图心 2,524（正好在图外面看整块） | 亮像素 **0**（全黑） | 亮像素 **51,275**（整块看得见） |
| 一个 576 权重的块铺满 **10.1 屏**，镜头贴在上面 | 亮像素 290,831（满屏热力图，神经元全被挡） | 亮像素 232（板子让开，看得见后面） |

自测里这几条是**数像素**验的：同一个机位、同一张图，把雾换回写死的 `320/1400` 立刻「非背景像素 0」，
换回自适应又是几万个；板子那一条用 `NF.plateFade(false)` 关掉淡出复现老行为做 A/B。
相关接口：`NF.fog` / `NF.fogState` / `NF.fogColorHex` / `NF.camFar` / `NF.plateFade` / `NF.graphBounds`。

## 架构（为什么能"全都要"）

**1. 数据用 SoA typed array**
`nPos` / `nAct` / `nBias` / `nThr` / `nIO` / `nCol` 等全部是平铺的 `Float32Array` / `Uint8Array`，
没有 per-neuron 的 JS 对象。10 万神经元下内存可预测、GC 不抖。

**2. 渲染用实例化 + 按需重绘**
所有神经元是一个 `InstancedMesh`，所有连接是另一个。改一个神经元只写一个实例矩阵
（`addUpdateRange`），不重建场景。空闲时 `requestAnimationFrame` 直接 return。
> 按需重绘踩过一个坑，记在这儿：OrbitControls 的滚轮 / 双指缩放会**自己**先调一次 `update()`，
> 相机在那一刻就动完了；循环随后再 `update()` 时它发现没东西可改，返回 false，于是这一帧被当成
> "没变化"根本不重绘。现象就是「滚轮转了、画面不动，鼠标动一下才"啪"地跳过去」——**空场景照样卡**，
> 因为它跟图规模无关。旋转 / 平移有阻尼，每帧 `update()` 都还返回 true，所以只有缩放会这样。
> 现在直接听 `controls` 的 `change` 事件：相机只要动过就标一帧重绘，顺手把屏幕坐标缓存作废
> （不作废的话，缩放过以后鼠标悬停会拿旧坐标挑神经元，挑错）。自测里 4 条断言盯着这件事
> （`NF.renderProbe`：帧数要涨、距离要真变近、缓存要作废、投影坐标要跟着动）。

**3. 拾取用均匀网格 + 3D DDA**
神经元走屏幕空间均匀网格，连线走屏幕空间线段距离判定。
两者都是 O(1) 级别，与图规模无关——这就是 23.8 万连接下拾取仍在 0.1 ms 量级的原因。

**4. 编译走 IR**
```
编辑器  →  图 (DAG)  →  校验/拓扑分层  →  IR  →  ┬─ PyTorch 后端  → .py + model.bin
                                                ├─ ONNX 后端     → .onnx（规划中）
                                                └─ 独立可执行后端 → .exe（规划中）
```
"全都要"靠的是这一层：新增一个编译目标 = 新增一个后端，编辑器本身完全不动。

**5. 编译产物与规模解耦**
图规模大时，权重、偏置、`src`/`dst`/节点顺序/激活编号全部写进 `model.bin`，
生成的 `.py` 恒定在几 KB。有权重块时**一定**走这条路（块权重动辄几十 MB，塞进源码没意义），
块的权重与块的形状 / 两端 id 索引也都在 `model.bin` 里，文件中段布局写在生成的 `.py` 末尾的注释里。
实测：1 万神经元 / 4 万连接的工程，源码 **5,453 字符**（早期版本内联索引时是 612,012 字符）。

## 工程文件：`.nforge` v3（分块二进制容器）

v2 是整份 JSON：超大工程一来就好几百 MB，`JSON.parse` 那一下必然爆内存，
而且「只想看看其中一小块」也做不到，必须整份读进来。v3 换成分块二进制容器：

```
+0    magic "NFORGE3\0"（8 字节）
+8    u32  headerLen
+12   u32  flags（保留，恒为 0）
+16   header JSON —— 索引表
...   块体依次拼接，块的 off 相对块区起点
```

header 里是**索引表**：每块的神经元区间 `[n0,n1)`、连接区间 `[e0,e1)`、包围盒、
压缩前后的字节数。**读文件时先只解析这个头，一块都不用解压**，
就能回答「这个工程多大、分了几块、每块在哪、占多少字节」。

### 兼容性契约：以后一边用一边加功能，旧工程还打得开吗

打得开。这不是口头保证，是格式本身的设计，而且有脚本盯着
（`node prototype/run_checks.mjs --only=compatcheck` 和 `py -3 tools/verify_compat.py`，
两边各 15 项断言，都是真跑真读）：

- 文件头里每个字段都是**可选键**，读的时候一律 `header.get` / `||`，缺了就当默认值。
  「加新功能」= 文件头多一个键、或者文件末尾多一段独立分区——老文件一个字节都不用改。
- 老软件遇上多出来的键和多余的尾巴也照样读：实测往文件末尾挂 8 KB 没见过的分区，
  读回来的神经元位置、连边、权重跟原文件**逐位相同**。
- 所以 **`version` 不跟着功能走**：它只在「改动已有字段的含义或排布」时才 +1，到今天从没动过。
  历史样本的文件头已经长出 **9 种互不相同的键集合**（`torch_demo.nforge` 9 个键、
  `op_from_js.nforge` 14 个键），全都还能读——这就是「一边用一边升级」在文件格式上的实际样子。
- 真到了必须 +1 的那天：**新软件仍然要能打开所有旧工程**（读入时把老布局就地升级）；
  老软件遇到新布局则**明确拒绝并说清是哪个版本**（「这份工程是按 v4 布局存的新版文件，
  当前软件只认到 v3……」），不再是一句笼统的「认不出的工程文件版本」。
- 兜底口子：可选键 `layout` 声明「这份文件真正的字节布局版本」。将来「加了新键但布局没变」
  的文件可以写 `version: 4, layout: 3`，当前这版软件就敢读它。**现在还没有任何写入方用它**，
  是留给以后的（写了就会多一个键，所以现阶段不写，免得跟历史样本对不上）。

一句话：**升级软件 -> 旧工程一定能开；降级软件 -> 新工程会被明确拒绝并告诉你原因。**
危险的动作只有一个——改已有字段的排布却忘了 +1，那会让老软件把新文件读成乱码。
所以改这块之前先读 `prototype/src/main.js` 里 `NF3_LAYOUT` 上面那段契约注释。

切块规则：神经元按下标连续切；**每条连接跟它的起点走**，
所以第 k 块自带「第 k 段神经元的全部出边」，只载入某几块拿到的仍是一张自洽的图。
代价是连接的终点可能落在别的块里——只载入部分块时这类连接会被丢掉，
界面会**如实报出丢了多少条**，不装作没事。

块体是一段定长小端布局，字段按 4 字节对齐，解压后可以直接建 typed array 视图零拷贝读，
不用逐元素搬：

```
[f32×3n 位置][u8 n 接口][pad][f32 n 阈值][u8 n 激活][pad]
[f32 n 偏置][u8 n 冻结][u8 n 自定义色开关][pad][f32×3n 颜色]
[u32 e 起点][u32 e 终点][f32 e 权重][u8 e 冻结][pad]
```

权重块跟神经元块区**并列**放在第二段里（由 `header.blocks` 描述），单独压缩、单独定位。
这一段有两种写法，`header.blocks.codec` 写明是哪种：

```
"raw" / "deflate"（老形式：整段一个 blob，向后兼容）
  [u32 'BLK1'][u32 nb][u32 sumK][u32 sumN][u32 totalW][u32 flags]
  [u32 k,n × nb][f32 权重 × totalW][u32 行 id × sumK][u32 列 id × sumN][u8 锁掩码 × totalW?]

"parts"（新形式，默认）：区里依次拼着各段，**每段自己就是上面那套布局、只是 nb = 1**
  header.blocks.parts[i] = { i, k, n, weights, off, len, raw, codec, bbox[6] }
```

为什么复用 `nb = 1` 的老布局、而不是另发明一套：解段那边**一个字都不用改**，
一段解出来就是一个只含一块的块区。为什么每段都带 `bbox`（该块两端神经元位置的包围盒）：
挑段的前提是"先知道这一块在空间的哪儿"——有了它，**不解压一个字节**就能判断相机靠近没靠近。
段之间首尾相接，各段 `len` 之和就是区块的 `len`，各段 `k`/`n` 之和等于区的 `rows`/`cols`，
`check_index` 两边都会把这些逐条对一遍。小于 2 KB 的段不压缩（压了也不划算）。

写入开关：Python `nforge.write(..., block_parts=False)`、浏览器 `NF.encodeV3({ blockParts: false })`
可以退回老形式——交叉对拍就是拿它验「两种形式解出来完全一样」。
只载入部分神经元块时，按包围盒挑不中的段**连读都不读**（不是"读了再丢"）；
挑中的段里，块的行列但凡有一个没载入就**整块丢掉**，面板会如实报出丢了几块、跳了几段
（跟丢连接一样，不装作没事）。

界面入口是 **文件 → 分块载入...**：选一个 `.nforge`，面板先只列出索引表
（块号、神经元区间、连接区间、压缩率、包围盒），勾选要哪几块再载入。
只载入部分块时神经元会**重新编号**（中间那些块没载入），面板里写明这一点。

实测 3000 神经元 / 11791 连接、切成 6 块：块体 deflate 压到约 **42%**，
整个文件 107 KB。自测里有一条断言盯着「v3 容器一定比同图的 v2 JSON 小」。

> 这条路（先看索引表、再挑块载入）是**手动**的；同一件事做成**自动**的就是
> 「流式载入」（见下一章）——打开只看摘要，相机靠近哪块才解压哪块。
> 本页的渲染层也已经按块拆好了（一块一个 `InstancedMesh` + 逐块视锥剔除，见「分块渲染」章）。

### 空间分块：让块 = 一小片空间

上面的切块规则有个隐含假设：**神经元的编号顺序大致就是空间顺序**。真模型里不是这样。
导入一张 4096×4096 的 MLP，编号是「一层接一层」，可神经元在 3D 里铺开的是一整层，
于是一块（一段编号）在空间里往往是**横跨整个模型的一层薄片**。这样「相机靠近哪块才解压哪块」
省下来的内存，跟它实际看到的画面几乎没关系——一块里什么都有。

所以 v3 加了一个可选的分块方式，写在文件头的 `order` 字段里：

| `order` | 块界是什么 | 什么时候用 |
| --- | --- | --- |
| `"linear"`（默认，旧文件缺省也是它） | 神经元的**下标区间** | 保存快、不改编号、不破坏引用 |
| `"spatial"` | 神经元的**空间区域**（Morton Z 序 + 八叉树） | 想「靠近哪片空间才解压哪片」的时候 |

算法三步，每一步都必须跟 Python 侧（`tools/nforge.py`）**逐位一致**——
两边写的文件要能对拍，差一位就红：

1. **量化**：每个神经元的坐标按整体包围盒归一化到 0..1023（每轴 10 位），全程 double。
2. **交织**：三个 10 位整数按 Z 序交织成一个 30 位 Morton 码（`x` 占每个三元组的最高位）。
3. **稳定排序 + 八叉树**：按码**稳定**排序（同码保持原序，所以结果唯一），
   再在排好序的数组上按 `(code >> 3*level) & 7` 递归切八份，切到每片不超过
   「每块神经元数」为止，叶子就是块区间。块数超过 4096 时把相邻叶子两两合并（安全阀）。
   用显式栈而不是递归——50 万神经元也不至于把栈顶穿。

**必须重排神经元，不能只存一张映射表**：块界得是连续的下标区间（边的分块也是按起点
区间切的），所以想让块对应空间区域，唯一的办法是**写文件时按空间顺序排好再重编号**。
代价说清楚：文件里的神经元编号跟界面上不一样了。位置、接口、阈值、激活、偏置、冻结位、
颜色、自定义色开关、名字表、每条边的两端、权重块的行列 id，全都按 `perm` / `rank` 一起搬，
所以**图本身没变**，只是换了一套编号——读回来是一张几何与连接完全相同、编号不同的图。
文件头的 `order` 字段写明了这件事；「分块载入」面板与左栏流式载入面板都会显示
当前这份文件是「按空间 Z 序分块」还是「按神经元区间分块」。

界面入口是 **文件 → 另存为空间分块工程…**，导出的文件名带 `.spatial` 后缀（不覆盖原来那份）。
它**不改内存里这张图**：界面上的编号、选区、撤销栈、引用一个都不动，
重排只发生在写文件的那一瞬间。

实测（`py -3 tools/bench_spatial.py`，随机 3D 图、编号与空间完全无关、每块软目标 2000）：

| 规模 | 切法 | 块数 | 文件 | 平均包围盒体积 | 块内坐标标准差 | 包围盒含一个随机点的块数 |
| --- | --- | --- | --- | --- | --- | --- |
| 2 万神经元 / 6 万连接 | linear | 10 | 668 KB | 996,043,437 | 289.0 | 10.0 |
| 同上 | **spatial** | 64 | 835 KB | **15,335,445** | **71.8** | **0.9** |
| 6 万神经元 / 18 万连接 | linear | 30 | 2.04 MB | 996,664,805 | 288.4 | 30.0 |
| 同上 | **spatial** | 64 | 2.40 MB | **15,527,514** | **72.1** | **1.0** |
| 20 万神经元 / 60 万连接 | linear | 100 | 6.88 MB | 996,787,246 | 288.4 | 100.0 |
| 同上 | **spatial** | 512 | 8.53 MB | **1,923,364** | **36.0** | **1.0** |

后两列才是收益：「看向一处大概要解压几块」从「整张图」变成「个位数」，
包围盒平均体积**收紧 65 倍（20 万神经元时 518 倍——块更小，收益更大）**，
块内坐标标准差收紧 4~8 倍。
代价也如实写：块数变多 → 文件**大 20% 左右**、写盘慢约一倍
（多出来的都是每块的头部与对齐填充）。

跨语言一致性有专门的对拍：`tools/verify_cross.py` 拿同一份文档，让浏览器与 Python
**各自**算一遍 Morton 码 / 稳定排序 / 八叉树叶子的块区间，断言两边**逐个相同**，
再逐位比对重排后的每一个字段与每一块包围盒（见「正确性验证」章，80 项）。

## 模型导入：`.onnx` → `.nforge`

`tools/import_model.py` 把已有的 ONNX 模型折成编辑器能直接打开的 `.nforge` 工程：
每个权重矩阵变成一层神经元，**每个权重变成一条带权边**，偏置折进神经元偏置，
张量的"输入 / 输出"标记变成「接口」标记。

```
py -3 tools/import_model.py model.onnx -o model.nforge
```

典型流程是先让框架导出 ONNX，再导入：

```python
torch.onnx.export(model, x, "model.onnx", opset_version=17,
                  input_names=["X"], output_names=["Y"],
                  dynamic_axes={"X": {0: "batch"}, "Y": {0: "batch"}})
```

**支持折进来的算子**（其余一律明确报错，绝不猜）：

| 类别 | 算子 |
| --- | --- |
| 全连接 | `Gemm`、`MatMul`（配一个常量 `Add` 当偏置） |
| 逐元素相加 | `Add`（两个激活张量相加：等于给两层各拉一条权重 1 的边再合成一个神经元） |
| 激活 | `Relu` `Sigmoid` `Tanh` `LeakyRelu`(α=0.01) `Elu`(α=1) `Gelu`(精确版) `Silu` |
| 形状直通 | `Flatten` `Reshape` `Identity` `Squeeze` `Unsqueeze` `Dropout` `Cast` |
| 常量 | `Constant` |

不支持的算子会打印**为什么**不支持，而不是猜一个近似值：

| 算子 | 报错理由 |
| --- | --- |
| `Softmax` | 整层归一化，不是逐神经元的激活函数，编辑器里没有对应的神经元语义 |
| `Conv` `MaxPool` `AveragePool` | 折成逐条边时**规模先爆**（一层几十万到上千万神经元、上亿条边），而且卷积共享的是「一个参数配一套规则模板」，折出来的不是「元素总数一致的一份数值」这种权重块。属于还没做的「聚合块」 |
| `BatchNormalization` | 推理期本可以先折进 `Gemm` 的权重与偏置，但本版还没做 |
| `LayerNormalization` | 依赖整层统计量，不是逐神经元语义 |
| `LeakyRelu(α≠0.01)`・`Elu(α≠1)`・`Gelu(approximate="tanh")` | 编辑器里的激活函数是定死的，悄悄换成默认值会**改变模型数值**，所以直接报错 |
| 转置进来的输入（`Gemm` 的 `transA=1`，且批量维≠1） | 会打乱张量元素与神经元的对应关系，猜错就是静默改数值 |

**按 batch=1 导入**：编辑器里是一张标量 DAG，批量维只能靠"复制整张网络"展开。
所以输入张量**除第一维外必须是静态形状**，第一维写死成 >1 的模型会直接报错
（提示把它写成 1、或者留成符号维度 `batch_size` / `None`）。
`dynamic_axes` 把批量维标成符号维度是最省事、也最常见的导出方式。

**大矩阵默认折成权重块**。`Gemm` / `MatMul` 的权重默认**不**展开成逐条边，而是折成一个
**权重块**（一段稠密权重矩阵 + 两端的神经元 id）：编译时就是一次 `matmul`，
进 `.nforge` 时是独立一段（见「权重块」章）。4096×4096 的矩阵因而不再需要展开成 1600 万条边：

```
py -3 tools/import_model.py big.onnx --blocks auto      # 默认
py -3 tools/import_model.py big.onnx --blocks always    # 所有矩阵都折成块
py -3 tools/import_model.py big.onnx --blocks never     # 都展开成逐条边
py -3 tools/import_model.py big.onnx --block-min 65536  # auto：权重数 ≥ 这个值才折块
py -3 tools/import_model.py big.onnx --block-dense 0.5  # 配 --prune-below 时改用非零占比判断
```

`--block-min` 默认 65536、`--block-dense` 默认 0.5。一旦同时给了 `--prune-below`，
`auto` 就改成看**非零占比**——稀疏连接展开成边更看得清，稠密矩阵折成块更省内存。

**边数天花板 67,108,864 条**仍然在：展开成边的矩阵受这个上限约束，撞上了会明确报错并建议改用
`--blocks always`。真需要稀疏边时就剪枝——剪枝会**改变模型**，
所以剪掉了多少条会如实打印出来，不偷偷剪：

```
py -3 tools/import_model.py big.onnx --prune-below 0.01   # 只保留 |w| ≥ 0.01 的边
```

其它开关：`--chunk-neurons`（每块神经元数上限）、`--spacing`（层间距）、
`--no-names`（不写名字表，超大模型能省下不少文件头体积）、`--no-compress`。

导入结果按层沿 X 轴排开，同一层的神经元在 YZ 平面上围成一圈——
这样一眼能看出层数、每层宽度、以及权重是正还是负。
导入后照常编辑、照常 `F7` 编译成 PyTorch 代码。

**边界（重要）**：导入是**单向**的。`.nforge` 是编辑器自己的工程格式，
改完之后**不能导回 ONNX**；目前也没有 `.pt` / `.safetensors` 的直接入口，
要先各自转成 ONNX。几十亿参数的模型不可能逐权重画出来，
得靠"权重块 + 抽样"呈现（见「权重块」章与「下一步建议」）。

### 没有快照的模型：跑它自己的代码建网再导出（`tools/import_bwc.py`）

有些模型仓库里根本没有「整网权重文件」——网络是**运行时用固定种子现生成**的。
`born-wired-cortex` 就是这样：`model/` 下 150 多个 Python 脚本，皮层连接由
`皮层连接_cortex_links.py` 现场长出来，仓库里没有任何 `.pt` / `.npz` / `.onnx`。
对这种模型，任何「读文件猜结构」的做法都是错的：猜出来的拓扑不是它。
唯一忠实的路是**跑它自己的代码把网建一次，再把结果导出来**——这就是这个导入器干的事。

```
py -3 -X utf8 tools/import_bwc.py <仓库的 model 目录> -o born_wired_cortex.nforge
```

开关：`--keep-born`（出生随机兴奋连接的保留比例，**本能连接永远不抽样**）、`--no-inhibit`、
`--min-w`、`--regions`（只要哪几个区；没要的区不导出，神经元重新编号）、
`--layout block|wall`、`--spacing` / `--gap`、`--chunk`（空间分块的粒度）、`--seed`。

本机实测（全 12 个区）：

| 指标 | 结果 |
| --- | --- |
| 建网耗时 | 14.5 s（143,796 个皮层神经元；视觉 23040 / 视觉细节 23040 / 听觉 30000 / 前额叶 53200 / 运动 160 / 运动记忆 3576 / 本体感觉 480 / 平衡感觉 120 / 机身状态 60 / 视觉运动 1920 / 多巴胺 200 / 抑制 8000） |
| 本能规则展开 | 308,809 条 → 落到网上 308,808 条（**一条都不抽样**，全标成固化） |
| 兴奋 / 抑制连接 | 11,926,165 / 4,890,945（抑制写成**负权重**，权重块热力图上是红的） |
| 导出 | 143,796 神经元 / **16,817,110** 条边 / **104.1 MB** / 写完 11.4 s |

只要 7 个运动相关区的小样本（`--regions`）是 12,596 神经元 / 365,261 条边 / 0.8 MB。

**必须走流式载入**：这 1,681 万条边整份载入会爆（实测全量读 53 s 后
`Array buffer allocation failed`）。走流式（见上一章）实测打开只要 22~35 ms
（只读 515 KB 文件头），靠近的块自动解压，10 秒后 37,628 神经元 / 131 万条边驻留、
帧耗时 0.50 ms。文件一大，「文件 → 打开大工程（按路径）」比 `<input type=file>` 那条路稳得多
（前者按字节区间直接读盘，后者先把整份交给浏览器）。

位置**不是原模型里的东西**，是导出时按 `--layout` 生成的：`block`（默认）= 每个区一个立方体块、
块拼成 4×3；`wall` = 每个区一面竖墙排成一条线。原模型里只有连接，坐标得由导出器给。

抑制边**不加阈值**：本机实测加了会在「模拟激活」里卡成死循环，所以一律不写阈值。

### 折平之后还剩什么、丢什么（导入的「失真」清单）

导入一定会丢信息，因为 ONNX 里根本没有编辑器要的那几个概念（坐标、神经元、名字）。
把每一类都摊开写清楚：能补的自动补上，补不了的原样记进工程文件，真会改变数值的**直接报错**。

| 类别 | 会不会失真 | 怎么处理 |
| --- | --- | --- |
| **数值** | 基本不失真 | 权重 / 偏置按 float32 逐位搬过来。两处例外：float64 常量会被截成 float32、`Cast` 到 float16 的降精度步骤不再复现——**这两类都写进工程文件头**，翻页到「模型独有信息」看得到 |
| **名字** | 一定会（ONNX 里没有） | 自动起名「算子 + 序号」，进编辑器随便改；`--no-names` 连名字表都不写 |
| **坐标 / 形状** | 一定会（ONNX 里没有） | 按拓扑分层自动铺开，见下面「形状是生成的」 |
| **结构** | 能补 | 折平**之前**那个算子图被完整记进工程文件（「来源表」），翻页就能看 |
| **共享参数**（同一个权重被多处引用） | **不失真** | **能表达，而且是真共享**：导入时把同一常量折出来的权重块编成「共享参数组」，组里共用同一份参数（改一处全组一起变、编译只存一份）。转了置的那种（同一张量一处 transB=1、一处 transB=0）导入器**故意不自动建组**（内存是列主序，自动建会算错），可以在界面里手工建（形状可以不同，元素总数一致即可）；走了逐条边的建不成组。终端与来源表会逐条写明原因 |
| **卷积 / 池化 / 归一化 / Softmax** | 折不成标量神经元，但**不再拒绝** | 折成逐条边时**规模先爆**（3×3、64→64 的卷积在 256×256 特征图上是 420 万神经元、上亿条边），而且它共享的是「一个参数配一套规则模板」。所以记成**算子节点**（算子级聚合块）：类型 / 名字 / 形状 / 参数张量原样保留，3D 里是一张参数热力图板子，编译时直接映射成 `F.conv2d` 这类。与神经元的唯一桥是**落点**（一个元素对一个神经元，个数必须一样） |
| **部分载入** | 图会不全 | 跨块的边被丢掉，丢了多少如实报数；只影响「看」，编译走的是完整文档 |

#### 来源表：折平之前的那个模型长什么样

`.nforge` v3 的文件头里多了一段 `source`：**逐个算子的记录**——算子类型、名字、折出来的神经元区间、
权重数、折进来的激活（比如 `Gemm` 后面跟的 `Relu`）、以及导入器认为你该知道的每一句说明。

界面右上角的「**结构视图 ⇄**」按钮（`F9`）就是翻到这一页：左边是**导入时记下的算子图**（不是现场猜的），
单击一个算子节点能在 3D 里选中它折出来的那批神经元，双击直接翻回 3D 并聚焦过去，
右边一栏是这个算子的明细（权重数 / 上游下游 / 折进来的激活 / 接口数）。

手工搭的工程没有来源表，翻过去也不会编一份假的：它显示的是**按当前图现场聚合**出来的粗粒度结构
（一个节点 = 一批同波次的神经元，权重块单独画），标题栏会写明「不是原模型的算子图」。

同一页的「**模型独有信息**」页签，放的就是上表里那些「3D 建模表达不了」的东西：
聚合块、精度变化、被跳过的算子、导入器写的说明（共享参数不在这里——它会真的建成共享参数组）。**翻回来就是原来的 3D 建模**。

#### 形状是生成的：四种重排

坐标是编辑器自己的概念。导入时按**最长路径分层**沿 X 轴铺开，同一层在 YZ 平面上围一圈——
一眼能看出层数、每层宽度、权重是正还是负。层的形状可以换：

```
py -3 tools/import_model.py model.onnx --layout ring     # 默认：每层一圈
py -3 tools/import_model.py model.onnx --layout line     # 每层一条直线
py -3 tools/import_model.py model.onnx --layout grid     # 每层一块网格
```

导入之后在界面里还能随时重排（菜单「视图」：按拓扑重排（层状）/ 重排成直线 / 重排成网格 / 力导向排布，
也可以让 AI 调 `relayout`）。力导向按连线把关系近的拉在一起，超过 6 万神经元会自动跳过
（步数按耗时预算随时停，不会把界面卡死，结果只是没那么收敛）。

#### 权值共享：现在是真共享（共享参数组）

「共享」这个词在模型里指的是两件很不一样的事，得分开说。

**① 同一个权重张量被多个算子用**（tied embedding、共享 transformer 层、共享 LSTM 权重）——
**能表达，而且导入时就是真共享**。导入器把同一个常量折出来的**权重块**编成一个**共享参数组**：
组里的块共用同一份参数——改一处全组一起变，编译出去只存一份，反向传播的梯度累加到同一段上，
所以它们永远保持相等。数值与原模型一致（**不算数值失真**，`exact` 仍然是 true）。

- 终端会打印建成了几组、每组几块、省下多少个权重；`--no-tie-blocks` 可以关掉，回到「各存一份副本」。
- 界面上：右栏「**共享参数组（权值共享）**」一节列着每一组，可以**解除整组共享**，也可以**把选中的块退出组**；
  在视口里框选两个及以上权重块，点「设为共享参数」就能手工建组。规则只有三条：
  **至少两块**、**元素总数 k×n 必须一样**（形状可以不同：3×2 和 2×3 就是同一段数值互为转置，
  各自按行主序读——容器读写、编译切片、剪枝、撤销、容器往返都按这条走）、
  **值取第一块那一份**（其余块原值被覆盖，可以 `Ctrl+Z` 撤销）。
- 来源表里记着（`shared` 字段），`F9` 翻到「模型独有信息」也有同一件事；脚本接口 `NF.blockGroups()` /
  `NF.blockShare(ids)` / `NF.blockUnshare(ids)`（AI 侧有同名的三个工具）。
- **建不成组的情况也说清**：逐条边的层没有「参数」这个概念（两个大小不同的边集本来就不是同一个参数），
  所以只有走权重块那条路（`Gemm` 这类、且 `--blocks` 允许收块）才建得出组；元素总数不一样的块也不能同组，
  因为共享的是同一段数值。同一个张量两处用了相反的转置时，导入器**故意不自动建组**
  （反过来的那处内存是列主序，硬编会算错），要建得在界面里手工框选建。没建成的，
  终端和来源表都会逐条写明原因，不会含糊过去。
- **共享块展开成连接时会先自动移出共享组**（值不变），提示里说清"它已经退出、其余成员不再和它联动"：
  展开出来的是每条一份权重，「同一个参数」按定义就没了，所以没有"一边展开一边还共享"这种事。

**② 卷积核在每个位置复用**（`Conv` / `MaxPool` / `AveragePool`）——问题不是「能不能标记共享」，
而是**规模先爆**：折成「每个输出元素一个神经元 + 每条 tap 一条边」，一个 3×3、64→64 的卷积
作用在 256×256 的特征图上就是 420 万个神经元、几亿条边，远超硬顶（16,777,216 神经元 / 67,108,864 条边）。
而且它共享的是「一个参数配一套规则模板」（stride / padding / groups / dilation），折出来的不是
「元素总数一致的一份数值」这种权重块。所以这类仍然默认报错，属于还没做的「聚合块」。

确实不要这些算子时可以显式跳过（**只有不改元素个数的算子跳得成**）：

```
py -3 tools/import_model.py model.onnx --allow-skip BatchNormalization,Dropout
```

只放行**不改元素个数**的算子（单激活输入 → 单激活输出，比如 `BatchNormalization` / `Dropout` 的推理期恒等）。
`Conv` / `MaxPool` / `AveragePool` 这种**会改元素个数**的连跳过都拒绝，理由会打印出来
（实测：`pool1：跳过 MaxPool 会把元素个数从 16 变成 4，后面的层就对不上了——这么跳折出来的图是错的`）：
不是不让跳，是跳了之后下游的层跟张量对不上，折出来的图本身就是错的。
跳了谁、跳了多少，会逐条打印、写进工程文件、翻页看得到，并把这份工程标成 `exact=false`。

#### 二期落地：算子级聚合块（Conv 这类模型真的进来了）

上面那个 ② 曾经是**唯一挡住「市面绝大多数模型」的地方**，现在补上了：在「神经元级」之上加了一层
「**算子级**」——一个算子节点 = 一个算子 + 若干参数张量。这不是「补一个算子」，是加一层表示。
原因仍然是硬约束：折成逐条边**规模先爆**（3×3、64→64 卷积在 256×256 特征图上是 420 万神经元、
几亿条边，而整个工程的容量有绝对天花板（16,777,216 个神经元 / 67,108,864 条边）），所以只有
「一个节点就是一个算子」这条路。

**做成了什么样**（每一块都有回归盯着）：

- **数据模型**：算子节点 = `{算子类型, 名字, 输入输出形状, 属性, 参数张量, 落点}`，撤销 / 序列化 /
  容器往返都按权重块那一套走。参数张量在 `.nforge` 里是**独立分区**（一个算子一段、可压缩），
  不进文件头 JSON——文件头只记 `ops.tensors` / `ops.elements` 两个数。
- **导入**：`Conv` / `MaxPool` / `AveragePool` / `GlobalAveragePool` / `BatchNormalization` /
  `LayerNormalization` / `Softmax` / `LogSoftmax` / `Concat` / `Transpose` / `Reshape` / `Flatten` /
  `Squeeze` / `Unsqueeze` 这类整块表达的算子不再报错，记成算子节点。实测一份 MNIST 量级的 CNN：
  **468 神经元 / 2560 连接 / 8 个算子节点**（Conv×2、MaxPool、BatchNormalization、Relu×2、Flatten、
  Softmax），前向跟 `onnx.reference` 对拍**最大偏差 1.19e-07**。
- **3D + 面板**：算子节点在视口里是一张**板子**——贴图是它最大的那个参数张量画成的热力图
  （蓝 = 正、红 = 负、越亮绝对值越大；整型参数用青色阶），边框颜色按算子类型取。板子默认摆在
  **落点神经元的重心**上，右栏「板子位置」里可以手动指定（勾上之后拖动 X/Y/Z，板子实时跟着动）。
  右栏还有一节「算子节点 #id」：类型 / 名字 / 输出形状 / 输出元素 / 参数张量（名字、形状、类型、
  min/max/均值/零占）/ 输入 / 落点 / 折叠进来的逐元素算子 / 备注。
- **落点**：算子与神经元之间只有这一条桥——算子的输出写进哪些神经元，**一个元素对一个神经元**，
  个数必须一样（不一样直接拒绝）。没有落点的算子（纯张量）只给下一个算子用。
- **编译**：PyTorch 目标直接映射成 `F.conv2d` / `F.max_pool2d` / `F.batch_norm` / `torch.softmax`
  （比折平更贴近原模型）。生成的模块里算子节点数与工程元数据一致，参数张量跟原模型**逐位相同**
  （卷积核没有被改过），前向偏差 1.19e-07。**C 后端（独立可执行）不支持算子节点**——图里有算子节点时
  明确报错并指路 PyTorch / ONNX，不生成一份算错的 C 代码。
- **模拟激活的边界**：卷积层没有标量数值可推，所以模拟只把板子点亮到「它的输入都到齐」的那一波
  就停，**不往下传**；右栏会写明「图里有 N 个算子节点」。要真值请编译出来跑——不假装能算。



```
py -3 tools/import_model.py model.onnx --order spatial        # 按空间 Z 序切块（默认 linear）
py -3 tools/import_model.py model.onnx --report model.json    # 把上面那张表写成 JSON
```

`--order spatial` 沿用「空间分块」那一套（块 = 一小片空间，包围盒收紧 60 倍以上），
代价是来源表里的神经元区间退化成**近似**范围（算子名仍然准确），工程文件里会写明这一点。
`--report` 把 `format / kind / generator / model / exact / auto / layerCount / nodes / spans / notes /
skipped / casts / precision / counts` 整份倒成 JSON，适合塞进流水线做门禁。

## 随机种子 · 可逆历史 · 自动保存 · 模块库

**全局随机种子**（菜单「增强 → 随机种子」）。批量生成、随机连接、随机权重、随机配色全部走
同一个 mulberry32 发生器；种子跟着工程存进文件，所以同一份工程编译两次，权重逐位相同。
换一个种子 = 重新掷一次骰子，不动种子 = 结果可复现。

**可逆的历史压缩**（「增强 → 历史与内存」）。撤销栈不是每步拷一整份数组，而是把平铺数组切成
固定大小的小块，新快照只重新拷**真正变过的块**，没动的块直接引用上一格的同一份内存
（函数式语言里的持久化数据结构 / 结构共享）。占用只跟「这一步改了多少」有关，跟模型多大无关；
而且完全无损——块里的字节原样存、原样写回，撤销后跟没改过一模一样。

> 顺带纠正一个说法：这不是哈希。哈希是单向的，算不回去。要做到「需要时再算出原来的数据」
> 又一步不差，正解就是结构共享。自测里盯这件事的断言是：同一个操作连做三次，第三次的快照
> 必须跟第二次**共享全部分块**，多一个字节都算错。

本机实测（12 万神经元 / 59.9 万连接，可复现）：上限 60 格的撤销栈，连做 59 步「每步改 1000 条
权重」，整套历史一共只占 **0.70 MB**；同样这些步老老实实整份拷贝要 **928 MB**，差 **约 1300 倍**。
框选 5 万个神经元只多占 **90 KB**——选择存的是 12.5 KB 的位图 + 真正变过的那几个块，不再拍整份全图。
单步开销 ≈ 改动量 × 4 字节（权重）/ 1 字节（位置），跟模型多大无关。

**权重块也走写时复制**。块的权重矩阵是原地改的（剪枝归零），而快照里的块对象是共享的，所以动
权重之前先把数组换成一份私有副本，老数组原样留在快照里。实测每剪一次 20 万权重的块，历史只多
一份 800 KB 的副本，撤销回来逐位相同（不是近似）。

**名称表也走了同一套**。神经元名字原来是「一个大 Map，每拍一格快照整份拷一份」——这是最后一个
跟改动量无关的开销：导入的模型默认**每个神经元都有一个名字**，12 万名字的工程里改一条权重也要多拷
1.8 MB，而且这块内存历史面板根本看不见（面板照旧报 4.5 MB，堆里其实多出 70 MB）。现在名字按索引
切成「每 1024 个神经元一段」的小 Map：快照只存段的引用，写之前对共享中的段做写时复制。实测同一
张图（12 万神经元、全部起了名字）：40 步撤销栈的堆增量从 **70.4 MB 降到 0.40 MB**（183 倍），
改一个名字只重拷那一段（约 20 KB），撤销回来逐字相同、重做也原路回去。面板现在把「平铺数组 /
权重块 / 名称表」三块分开列。

**上限 60 格，其中一格是「当前位置」，所以真能往回退 59 步**（上限在面板里可以调到 200 / 1000；
因为它只跟改动量有关，调大不会爆内存）。

**自动保存**。改动后安静 8 秒，把 v3 容器字节写进浏览器 IndexedDB（跟手动保存完全等价）；
**下次打开默认直接接回来，不再问一句**（2026-09 改的默认值：以前是顶上弹一条横幅问「要接回吗」，
用户实测每次开机都被拦一下、不点它就一直挂在画面上）。接回期间那条横幅改成**报进度**用：
写着工程名 / 时间 / 体积，带「以后不自动接回」和「收起」，接完自己消失，状态栏也会落到
「就绪 — 已接回上次的自动保存（…143,796 神经元 / 16,817,110 连接）」。
「要不要接回」由本机设置管（`nf.autorestore`：auto 默认 / ask 先问一句 / never 不问也不接），
菜单「增强 → 启动时接回上次工程」点一下循环。默认自动之后有个兜底：**连续两次没接回来**
（多半是这份存档一载进来就崩）自动退回「先问一句」，免得变成一开机就崩的死循环。
超过 400 MB 的图会跳过，不阻塞主线程。

**模块库**（「增强 → 模块库」）。框选一块子图 → 起名字 → 封装成模块。入口 / 出口按
「有没有跨界连接」自动判定，也可以关掉「保留接口标记（外界输入 / 输出）」。之后随时把模块
原样复制到放置光标处，复制完光标自动顺移出这块的包围盒，接着放不会叠在一起。
复制出来的是普通神经元和普通连接，**编译时一律摊平**——所以对代码生成、权重块、导入导出
没有任何影响。模块库存在浏览器里（跨工程可用），也能导出成 JSON 带到别的机器。

## 全局体检 · 剪枝 · 分布直方图

搭到几万个神经元之后，「哪里接错了」靠眼睛是看不出来的，所以这三件事都做在数据结构上，
不是做在画面上。

**全局体检**（编译报告里自动出现，脚本接口 `NF.insight()`）。一次遍历算出六类东西：

| 查什么 | 什么意思 |
| --- | --- |
| 连通分量 | 整张图其实是几块？最大一块多少个神经元 |
| 死神经元 | 有进有出，但**不在任何「输入 → 输出」通路上**——改它不影响结果 |
| 只进不出 / 只出不进 | 从输入摸得到、却到不了输出（或反过来） |
| 无关子图 | 整块跟输入 / 输出都不连通（比如放了一半没接上去的那一片） |
| 零权重 / 极小权重 | 接上了但权重是 0，编译出来等于没接 |
| 权重绝对值上限 | 用来估量化误差、判断权重尺度 |

死神经元和无关子图这两类**后面都挂了「选中这 N 个」按钮**——报告不是给你看的，是给你点的。
体检有一个明确的分析上限（折算 200 万条等效边），超了就在报告里**直说「这次跳过了连通分量和
死神经元，只统计了零权重」**，绝不假装算过。

**剪枝与清理**（「增强 → 剪枝与清理」，脚本 `NF.pruneByWeight` / `pruneRandom` / `pruneUnused` / `pruneOrphans`）：

- 按权重阈值剪：`|w| < 阈值` 的连接可以**归 0**（连接还在、可视化还在，编译出来等于没接）
  或**直接删掉**（连接数真的变少，场景也更轻）。勾上「连权重块一起处理」就一块儿算。
- 随机稀疏化：按全局种子随机丢连接，保留比例自己填。**同一种子剪两次，剩下的连接逐条相同**。
- 清理无用神经元：删死神经元 + 孤立点（一根线都没有的）。
- 删无关子图：整块跟输入 / 输出都不连通的，一次删干净。

每一步都是**一次可撤销的编辑**（Ctrl+Z 整体回来）。所有"要动数据"的动作都先 `dry` 报数，
确认了才动手——AI 工具 `prune` 的 `dry` 默认就是 true。

**权重直方图**（「增强 → 权重直方图」，脚本 `NF.dist()`）。两遍 $O(n)$ 扫描，
**不抽样、不排序、不建临时大数组**，200 万条连接也是几十毫秒。权重经常横跨好几个数量级，
所以给两种分箱：

- **线性**：在 `[-最大|w|, +最大|w|]` 上等宽，看正负对称性和零附近堆了多少；
- **对数**：按 `|w|` 的常用对数等宽分箱，**精确的 0 单独占一箱**，看"大头在哪"。

纵轴默认走对数刻度（权重分布常常有一根压倒性的柱子，线性刻度会把别的全压平），可以关掉看真实比例。
面板上还会算一个**权重集中度**：`|w|` 最大的 1% 连接承担了多大比例的权重总量。
用固定 512 箱的对数直方图从大到小累积算出来——**不需要给几百万条连接排序**。
这个数很大（比如 80%）就说明这张图其实是被极少数连接撑起来的。

图上**按住拖出一段区间**，就能把它「选中这些连接」/「权重归 0」/「删掉这些连接」（都可 Ctrl+Z）。
同一个面板切到**「神经元连接数分布」**就是度分布：一条连接给两端各记一次度，用它找枢纽神经元和
孤立点，配合左栏「神经元大小按连接强度」一起看，谁是枢纽一眼就出来。

诚实边界：**权重块不参与按条统计**——一块就是一整个矩阵，没有"按条"的概念。要在直方图里按条看，
得先在界面里把块「展开成连接」（超过 20 万权重会被拦下）。另外一次最多选中 10 万个对象
（选中网格本身就几百 MB），超了会提示你把区间收窄；**归 0 / 删除不受这个上限限制**。

## 搜索定位 · 分组 · 视角书签 · 第二视口 · 旋转动画

**搜索与定位**（「增强 → 搜索与定位」）。名称 / 分组是子串匹配，编号写 `12` 或 `12-40`，
颜色写 `#rrggbb`（按屏幕上真正显示的那个颜色找），接口写「输入 / 输出 / 双向 / 无」，
激活函数写 `relu` / `gelu` 这类名字，「全部」就是这几种一起找。找到就选中，还能直接飞过去。
面板里同时能管分组：改名、解散、一键清掉那些**一个神经元都没用的组名**。

**分组**是工程里的**真实数据**：`G.groups` 存组名，`G.gsets[组号-1] = { a: 升序的成员编号 }` 存**成员关系**，
`nGroup` 只是「主分组（组号最小的那个）」的缓存，留给老代码和老文件用。跟着 `.nforge` 一起存
（v2 的 JSON 和 v3 的容器都有；v3 里单独放在文件末尾的 `ext` 分区），跟着撤销栈一起退，
也能跟着模块被封装带走。但它**只影响组织和查找，不影响编译**——编译只看接口标记和连接。

**一个神经元可以同时在好几个组里**（集合语义，不是单选），所以「他在哪个组」要按一组名单来读：

| 接口 | 语义 |
| --- | --- |
| `NF.groupAdd(ids, '名')` | 把这些人**加进**这个组，他们原来所在的组一个都不动 |
| `NF.groupRemove(ids, '名')` | 只把这**一个**组摘掉，别的组不受影响 |
| `NF.setGroup(ids, '名')` | 「**只属于它**」：先清掉这些人原来的所有组，再放进这一个（右栏属性面板那个下拉框走的就是这条） |
| `NF.groupsOfNode(i)` | 这个人所属的**全部**组名（主分组用 `NF.groupOf(i)`，跟以前一样） |
| `NF.groupMembers('名')` / `NF.groupCount('名')` | 一个组的全部成员编号 / 人数 |

**手动隐藏 · 神经元列表**（视口工具条的「神经元列表」按钮 / `Ctrl+L` / 「增强 → 神经元列表」）。
**隐藏只影响显示与拾取**：数据、统计、编译、导出、训练一概不动，也不会写进编译产物。
被藏起来的东西在画面里**点不到**（故意的：看不见的不该被点到），所以这张表就是把它们捞回来的地方：

- 一屏看全每个神经元的编号 / 名称 / 所属分组（多归属全列出来）/ 接口 / 激活 / 入出度 / 显示状态。
- 可以逐个藏 / 显示，也可以批量：「隐藏选中的」「显示选中的」「把筛出来的这一批藏 / 显示」「全部显示（清掉所有手动隐藏）」。
- 筛选写法跟「搜索与定位」一样，外加一档「隐藏与显示都要 / **只看被隐藏的** / 只看显示的」。
  藏丢的东西就靠「只看被隐藏的」找回来（还能「把筛出来的全部选中」再「定位」）。
- 快捷键：`H` 藏起选中的，`Shift+H` 显示选中的。两者都是**可撤销的编辑**（`Ctrl+Z` / `Ctrl+Y`）。
- 脚本 / AI 接口：`NF.setHidden(nodes, edges, on)`、`NF.hiddenCount()`、`NF.hiddenNodes()`、
  `NF.hiddenEdges()`、`NF.showAllHidden()`（这条不走撤销栈）、`NF.neuronHidden(i)`、`NF.edgeHidden(e)`。
  **连线只要任一端点被藏，它自己也跟着算藏**——不然会剩半截线头挂在空气里。
- 存进哪里：v3 容器放在文件末尾独立的 `ext` 分区（可 deflate，老软件读到不认识的 `header.ext` 会忽略它，
  不影响打开）；v2 的 JSON 里是 `hidden: { n: [], e: [] }` 与 `groups.multi`，两个格式都能往返。
- 代价（实测，143,796 神经元 / 16,817,110 连接）：藏一个人约 **0.3 秒**，藏 2000 个约 0.35 秒。
  这笔钱的大头（约 0.23 秒）是**撤销快照**的固定开销——快照要把每一列跟上一格逐块比一遍
  （16,817,110 条边 × 7 列），跟藏了多少人基本无关；剩下的才是「重写他身上的边」。
  所以隐藏是**一次性动作**，不是每帧都跑的路径。

**视角书签**（「增强 → 视角书签」）。上百万元神经元时靠拖鼠标是拖不回同一个角度的，
存成书签一点就回去，可以导出 / 导入 JSON 带到别的机器。
**边界：书签只存在本机（localStorage），不进 `.nforge` 工程文件**——它记的是相机位置，
跟工程数据本来就不是一回事。

**视角中心**（「视图 → 以选中为中心」/「选中就换旋转中心」，快捷键是 `Shift+F`；左栏还有一块「相机」面板）。
默认轨道控制的旋转中心固定在世界原点 —— 图一摊大，选中了远处那一片再转，画面立刻甩飞，这就是「视角只能盯着原点」。
现在有两档：**以选中为中心**（`Shift+F`，只把旋转中心搬过去，方向、视距都不动，镜头是平移而不是重新取景，
所以缩放档位不会被顺手改掉）、**聚焦选中**（`F`，连视距一起调好，把选中对象框进屏幕；什么都没选就框住整张图，
图是空的才退回初始视角）。选中集合包括神经元、**连线的两个端点**和权重块 —— 只选一条连线也能绕着它转。
「**选中就换旋转中心**」是个开关，勾上以后每次改选择，旋转中心自动跟过去（拖动中 / 框选中不跟，免得手抖拽歪镜头）。
平移镜头用方向键或左栏方向盘，**按住 = 持续平滑滑行**（速度按指数曲线爬升、松手按另一条曲线缓停），
不再是「一按跳一格」；速度跟当前视距成比例（约 0.55 视距/秒，`Shift` 是 4 倍），所以拉近看细节挪得细、
拉远看全局挪得快，任何缩放档位下手感都对得上；注视点和相机一起挪，朝向和视距都不变。
方向盘按钮按住就是同一套滑行逻辑（指针拖出按钮也不会断），快速点一下 = 一小段平滑位移 + 缓停。
要给脚本 / AI 用的一次性位移仍然有：`NF.camPan(±1, ±1, big)` 是瞬时一步（平时 4%、`Shift` 16%）。

**第二视口**（「视图 → 第二视口」）。右上角一个小窗，可以是顶视 / 前视 / 侧视 / 跟随主相机。
它是**同一台渲染器对同一个场景画第二遍**（scissor 裁出来那一块），不新建 WebGL 上下文，
所以几乎不额外吃资源，小窗里的内容跟主画面**必然一致**——不可能出现两个渲染器状态不同步。

**导出旋转动画**（「视图 → 导出旋转动画」）。绕当前焦点转一圈，用浏览器自带的 `MediaRecorder`
录画布，直接出 `.webm`。转速是按秒数算的（正好一秒一圈），没转完一圈会如实告诉你。

### 循环网：图里有环也能编译（时间展开）

连线是有向的，而且**允许成环**——反馈连接、递归、自环都可以画。有环的图不是"改一改就行"，
而是被当成**循环神经网络**编译：给环一条时间轴。

- **哪些边算回边**：落在同一个强连通分量（SCC）内部的边。其余边照旧在同一拍里按拓扑波次往前传。
- **回边读上一拍的值**：第 0 拍的回边输入是 0。展开之后整张图还是 DAG，波次求值的代码一行都没改。
- **展开多少拍**：编译对话框 → **训练** 页里的 `NUM_STEPS`（默认 8，可设 1 ~ 4096）；
  生成文件里的 `NUM_STEPS` 也是它，改那个常量同样生效，不用回编辑器重编。
- **自环**就是最短的环（一条边自成回边），走同一条路。

三个目标都出得来，形态不一样：

| 目标 | 循环网长什么样 |
| --- | --- |
| PyTorch | `forward(x)` 接 `(B, T, 输入数)`，返回 `(B, T, 输出数)`。回边权重照常是 `nn.Parameter`，`backward()` 就是沿时间反向传播（BPTT） |
| ONNX | 同一条 PyTorch 图导出。**T 被写死成 `NUM_STEPS`**（ONNX 只把 batch 当动态维）——要换步数就改 `NUM_STEPS` 重新导出 |
| 独立可执行 | `model.c` 是**流式**的：每读一行输入就是一拍，内部留着上一拍的状态。适合接实时信号 |

界面里的**模拟激活**按拍播放：标签写"第 N 拍 · 第 M 波"，回边点亮的是它上一拍拿到的信号
（所以一条边的终点可能比起点先亮，这是对的，不是显示错了）。

**实测（用真模型验的，不是玩具例子）**：`_dump/bwc_sub.nforge` 是从
`born-wired-cortex`（143,796 神经元 / 16,817,110 连接）里切出来的一张连通子网——
8,000 神经元 / 11,669 连接 / **973 条回边**（含 515 条自环）/ 1,963 个波次 / 64 入 1 出。

| 验证 | 结果 |
| --- | --- |
| 三个目标编译 | `errors = []`，PyTorch 106 KB / C 556 KB |
| 生成的 `.py` 用真 PyTorch 跑前向 | 通过，`(B,T,64) → (B,T,60)` |
| 逐神经元对拍（有阈值那档） | 被点亮的抽头**全部逐点一致**，最大偏差 **1.192e-07**（float32 舍入） |
| 逐神经元对拍（把阈值压到 -1e9 那档） | 60 个抽头里 **59 个精确一致**，剩下 1 个两边都是 0 |
| 批次维 | B=3 与 B=1 逐样本一致；全零输入时输出恒为 0 |

脚本在 `_dump/_bwce2e.mjs`（载入 → 编译 → 落盘）+ `_dump/_bwcpy.py`（真跑 PyTorch 对拍），
日志 `_dump/bwc_e2e.log`。

**诚实边界**（这几条是真的编不了，不是没做）：

- **权重块 / 算子节点自己卷进环里** → 拒绝编译。它们不是标量连接，按"读上一拍"切开会静默算错，
  所以宁可报错也不出文件。先断开那条回路再编。
- **流式载入只载了一半的工程** → 拒绝编译：内存里没有那些神经元和连接，编出来是一张跑得动、
  但数字对不上的残缺模型。
- **指向输入接口的边**在生成的模型里一律被忽略（输入接口的值每拍由外部直接写进去），
  报告里会把这类边单独数出来告诉你。
- **指向输出接口的重复边**、**没有入边的输出接口**仍然是错误——那是建模错误，不是循环结构问题。
- 编辑器里的**激活阈值只在模拟激活里生效**，不进编译产物（见「已知限制」）。

### INT8 量化导出（编译对话框 → 量化）

勾上之后，生成的 `hand_built_net.py` 里会多出 `quantize_int8` / `quant_stats` / `export_int8` /
`load_int8` / `check_int8`，命令行加 `--quantize-int8 model_int8.npz` 就能导出并跟原模型对拍。
面板上**先用当前权重估一遍量化误差**（上界 = 最大权重 ÷ 254），不用等生成了 Python 才知道。
本机实测：权重 0.6 KB → 0.1 KB（**3.79×**），量化误差 4.271e-03，还原后输出偏差 7.426e-03。

> 边界说清楚：这是**权重**量化（int8 + 每个张量一个 scale，per-tensor 对称量化），
> **激活还是 float32**。所以它省的是模型体积和带宽，不是算力——真正的全 int8 推理要靠专门的运行时。

这三条链路都在真机上跑过（`py -3 tools/verify_codegen.py`，13 项全过）：

| 验证 | 结果 |
| --- | --- |
| 生成的 `.py` 能被 torch import、前向 | 通过 |
| 前向结果 vs 独立 numpy 参考实现 | 最大偏差 **1.66e-07** |
| `--export-onnx` 导出（opset 17，dynamic batch） | 通过，10~16 KB，算子全是标准算子 |
| ONNX vs PyTorch 对拍 | **0.000e+00**（用 `onnx.reference`，本机没有 onnxruntime 也能测） |
| `model.c` 用 gcc 编成 exe | 通过，55.6 / 57.1 KB，只挂 `KERNEL32.dll` + `msvcrt.dll` |
| exe 输出 vs PyTorch 对拍 | 最大偏差 **1.28e-07** |
| 十一种激活函数（八种无状态 + 记忆 / 漏电积分 / 脉冲三种有状态）全覆盖 | 通过 |
| `--train --data x.npz` 训练骨架 | 通过，损失正常下降，能存 `trained.pt` |

路上修掉的两个**真问题**：

- `torch.index_add` 在索引有重复值时**导出 ONNX 会静默算错**（实测偏差 **1.759e+00**）。
  换成全宽 `scatter_add` 后降到 **0.000e+00**。
- 生成的 PyTorch 与生成的 C 对 GELU 的取法不一致：`F.gelu` 默认是 erf 精确版，
  而编辑器里的模拟和生成的 C 用的是 tanh 近似版，两者在 |x|≈2.7 处差 **4.73e-04**——
  同一张图在编辑器里和在编译产物里会算出不同的数。现在四处（JS 模拟 / PyTorch / ONNX / C）
  统一用 tanh 近似版，并把用到的激活函数编号在编译期就写成常量（顺带甩掉了
  `torch.onnx.export` 的 TracerWarning）。

**诚实边界**：浏览器里编不出 C——gcc 得在你自己的机器上跑，所以编辑器给你的是
`model.c` + 一键编译脚本；独立可执行**只做推理**，C 里没有反向传播，要继续训练请用 PyTorch 目标；
含权重块的工程走不了 C 这条路（块是矩阵乘，展开成连接会很大）。

**训练**在「编译 → 训练」页里先定义好，再生成文件：优化器 / 学习率 / 权重衰减 / 损失 / 轮数 /
批大小 / 数据文件 / 设备 / 种子写进生成代码里的 `TRAIN_CFG`，`--train --data x.npz` 直接就能跑。
骨架里还带验证集划分（`val_split` / `val_every`）、每轮指标与 `--history` 的 JSON 曲线、
cosine / step 学习率调度、梯度裁剪、`log_every` 打印节流，以及**完整断点续训**
（`--save` / `--resume`：权重 + 优化器 / 调度器状态 + 轮次 + 随机数流 + 内部状态一起存，
中断续训与一次跑完逐位相同）。
这是**骨架**不是成品训练框架：它负责把「可视化搭好的网络」接到标准训练循环上；
数据增强、早停、多卡、混合精度这些留给你或 AI——反正每次改一下 TRAIN_CFG 重新生成就行。

## 正确性验证

生成的 PyTorch 代码里，`forward()` 不是逐节点循环，而是把图拆成"拓扑波次"，
每一波用 `index_select` / `scatter_add` / `scatter` 批量并行求值——这样深层网络也只需
几十次向量化运算，而不是几千次 Python 循环。

### `.nforge` 的 JS 与 Python 双向对拍

同一个容器格式两边各写了一份（浏览器 `prototype/src/main.js` 12.5 节、Python `tools/nforge.py`）。
这种双实现最容易犯的错是**只读得懂自己写的那份**，所以要交叉验证：


覆盖面：300 神经元 / 1200 连接、**5 个权重块**（形状与有无锁掩码都覆盖到）、
**切块大小两边故意不一样**（浏览器 256 / Python 64，所以文件头必须自描述）、

每块的包围盒必须等于「按 perm 取坐标」算出来的那个数，重排后的每一个字段（含名字表、
边的两端、权重块的行列 id）**逐位**比对，两个方向都走。

## 已知限制（诚实说明）

- **环是支持的**（反馈 / 递归 / 自环都行，见「循环网」那一节）：落在同一强连通分量里的边按回边处理，
  编译时读上一拍的值、整张图按时间展开。真的编不了的只有两种：**权重块 / 算子节点自己卷进环里**
  （按「读上一拍」切开会静默算错，所以宁可报错），以及**流式载入只载了一半的工程**。
- **容量按需增长，只有一条绝对天花板：16,777,216 个神经元 / 67,108,864 条连接**
  （`CAP_HARD_N` / `CAP_HARD_E`）。初始只开 8,192 / 16,384，写入前按需翻倍长上去，不再一次铺平
  那么大的数组（老文档里"死上限 50 万 / 200 万"的说法已经过期）。
  **这是内存的物理上限，不是性能承诺**：能舒服地跑到多大由机器决定 —— 性能表里 50 万 / 200 万
  那一档占 461 MB 堆、稳在 60 fps；规模翻几倍，内存和帧耗时都跟着涨。
  超过绝对天花板的工程**会明确报错并告诉你怎么办，不会静默截断**：
  用「文件 → 分块载入」只挑需要的块，或者在 Python 侧先用 `tools/` 的脚本切一张子网。
  born-wired-cortex 全模型 143,796 神经元 / **16,817,110 连接**在绝对天花板之内（约占连接上限的

- 编译产物 = **定义 + 推理 + 一个可选的训练骨架**：勾「训练」会生成 `--train --data x.npz`

- **AI「给自己长本事」的边界，说清楚**：它能往 `%APPDATA%\NeuroForge\tools\` 里写新工具、

  但有三件它做不到：① 改不了 exe 里**编译进去**的工具表（那是 Rust 代码 + 打包产物，不是运行时数据）；

  中间还自己写了一个自定义工具来扫非有限值。产物经**独立复验**（不进软件，直接读 `model.bin`）：
  与基线逐条对比，只有运动区 5593 条可塑入边被 ×1.5，其余 1600 多万条一条没动、冻结的一条没动、
  bias 一条没动，编译产物真能前向（(1,8,480) → (1,8,160)，数值有限）。
- **AI 碰不到你的 API Key**：工具表里没有任何一个能读写 Key 的工具（只有你能在设置里改）。
  理论上唯一能间接碰到的是 `sys_write_text` 去改 `settings.json`，但那也要用户开着「读写文件」那道门，
  而且下一轮开机合并还会从 `settings.bak.json` 把非空的 Key 捡回来。
- **Key 在本机是明文存的**：`%APPDATA%\NeuroForge\settings.json` 就是普通 JSON，没有加密、
  没走系统凭据库（DPAPI / 凭据管理器 / Keychain）。同一个 Windows 账户下的任何程序都读得到它。
  要更严的环境应该改成走系统凭据库——**这件事还没做**，先如实写在这里。
- 撤销栈**不再吃大内存**（见「可逆历史」章）：12 万神经元 / 59.9 万连接、上限 60 格、每步改 1000
  条权重，实测整套历史只占 0.70 MB（整份拷贝要 928 MB），框选 5 万个神经元只多 90 KB。权重块走
  写时复制，剪枝一次也只多一份改动过的块；名称表按 1024 个神经元一段分块（改一条权重本来也要拷一遍
  12 万个名字，实测 40 步 70.4 MB → 0.40 MB）。这几件都实测过，数字见「可逆历史」章。
- **手动隐藏 / 多归属分组的代价已经压到底了**：用户那套工程（143,796 神经元 / 16,817,110 连接）实测
  藏 1 个神经元 ~0.28 s、一次藏 2000 个 ~0.35 s、「全部显示」~0.25 s。看着不算快，但里面**约 0.23 s
  是撤销快照的固定开销**（每一步都要把 1681.7 万条边的 7 列逐块比一遍），所以连"什么都不改"的空调用也是
  0.23 s——也就是说这条路径已经到底，再快只能动"每步都存快照"这个设计。
- **隐藏和分组不进编译产物**：藏起来的神经元照样参与编译（编译报告里会写明「手动隐藏的 N 个神经元 /
  M 条连接照常参与编译——这不是剪枝」），分组也不写进产物。它们只存在**工程文件**里（v2 的
  `hidden` / `groups.multi`、v3 的 `header.ext` 分区），换台机器打开还在。真要剪掉图的一部分，
  用剪枝（会改数值）或导出一张子网。
- 工程文件格式已升到 **version 3**（分块二进制容器，见下文）；v2 / v1 的 JSON 工程仍可读，
  也能用「导出 JSON 工程（v2 兼容）」写回去。**version 只在字节布局真的变了时才 +1**：
  加新功能只是往文件头多写一个可选键、往文件末尾多一段分区，所以旧工程一定能被新版本打开
  （`py -3 tools/verify_compat.py` 专门盯这件事）。反过来，用**更新**的软件存出的工程，
  老软件会明确拒绝并说清它是什么版本，不再只丢一句「认不出的工程文件版本」。详见「兼容性契约」。
- GPU 实例缓冲增长时，旧的 GL buffer 依赖垃圾回收释放，不做显式销毁（发生频率低，影响可忽略）。
- 桌面版依赖系统自带的 WebView2 运行时（Win11 预装）。改完代码不会自动更新**已安装**的那份，
  要重新 `npm run build` + 重跑安装包。
- **流式载入现在会驱逐远处的块**：磁盘分块、渲染分块、按需解压、超预算驱逐，四件事都已做完
  （见「流式载入」章）。但要看清驱逐省的是什么——数据模型是**静态预分配**、实例缓冲**只涨不缩**，
  所以**驱逐并不把内存还给系统**，它买的是「在上限之内可以无限漫游」。上限是硬的：装不下时连
  「看得见的块」也按远近丢（先丢远的；选中的 / 正在用的永远不丢），被丢的会记账（dropVisible）；
  只有连选中的都丢不动时才会停止载入并提示一次。~~按空间重新分块~~ **已做**
  （`order: "spatial"`，见「空间分块」节）：块界从神经元区间换成空间区域，包围盒平均体积收紧约 65 倍。
  ~~**权重块区按块读**~~ **也已做**：权重块区在文件里是「一块一段」存的，每段带包围盒，
  挑段时一个字节都不用解压；实测只驻留 3 块时权重块只读了 6,048 B（整段 48,317 B）。
  另外注意：空间分块会让文件大约 20%（块变多了），这是它的代价，不是 bug。
  「每帧的 GPU 提交」由分块渲染负责省，「内存里放多少」由流式载入（按需解压 + 驱逐）负责省。
- **模型导入是有边界的**：只吃 ONNX。逐神经元的算子折成神经元 + 加权边；
  `Conv` / 池化 / 归一化 / `Softmax` / `Concat` 这类**整块表达**的记成**算子节点**；
  两者都覆盖不到的算子仍然明确报错（`Gather` 这类会打一行为什么）。
  批量维必须是 1。折成边的矩阵受绝对天花板（67,108,864 条边）约束，算子节点不受——它的参数走独立分区。
  `.pt` / `.safetensors` 没有直接入口，要先自己转成 ONNX。
- **导入的上限就是"整个工程"的容量天花板，流式载入救不了这条**：
  导入器（`tools/import_model.py`）与编辑器（`prototype/src/main.js`）两边写死同一个数：
  `CAP_HARD_N = 16777216` / `CAP_HARD_E = 67108864`：编辑器按需扩容，但也不是没有顶——顶就是
  内存装不装得下。
  导入器的 `--max-neurons` / `--max-edges` 可以调，但调过编辑器那个数，产出的工程编辑器打不开。
  流式载入省的是**同一时刻驻留多少**（按需解压 + 驱逐远处的块），它不改数据模型、也不改文件里的边数——
  所以"只载入一部分"能解决"同时装不下"，解决不了"文件里本来就有 200 万条以上"。
  真撞上的三条路：把大矩阵**折成权重块**（不占边数）、`--prune-below` 剪枝（**会改数值**，剪多少会打印）、
  或者换个更小的模型。**分片成多个工程还没做，这里不承诺。**
- **共享参数（同一个权重被多处引用）现在是真共享**：导入器把同一常量折出来的权重块编成「共享参数组」——
  组里共用同一份参数，改一处全组一起变、编译只存一份、梯度累加到同一段上。建成了几组、省下多少个权重，
  终端与来源表都会写明；形状不一致或走了逐条边的那些建不成组，也会逐条写明原因。
  不想建组：`--no-tie-blocks`。手工建 / 退组在右栏「共享参数组（权值共享）」（脚本接口 `NF.blockShare`）。
- **卷积（`Conv` / 池化 / 归一化 / `Softmax`）现在进得来了**：不折成标量神经元（折了规模先爆：
  一层几十万到上千万神经元、上亿条边），而是记成**算子节点**——一个节点 = 一个算子 + 若干参数
  张量，与神经元的唯一桥是**落点**。3D 里是一张参数热力图板子，右栏能看形状与参数统计，
  编译时直接映射 `F.conv2d` / `F.max_pool2d` / `F.batch_norm` / `torch.softmax`。
  **C 后端（独立可执行）不支持算子节点**：图里有算子节点时会明确报错，让人改用 PyTorch / ONNX。
  模拟激活只把板子点亮到「输入都到齐」那一波就停，不往下传（卷积没有标量数值可推）。
  剩下没覆盖的算子（`Gather` 这类）仍然明确报错，`--allow-skip` 只放行不改元素个数的那些。
- **折块的代价**：折成块之后**单个权重在 3D 里看不出来**，
  要看细节得先在界面里「展开成连接」（超过 20 万权重会被拦下）。共享组里的块点展开时会
  **先自动移出共享组**（值不变）再展开，提示里说清"它已经退出、其余成员不再和它联动"——
  展开成边就没有「同一个参数」这回事了。
- **导入是单向的**：`.nforge` 是编辑器自己的工程格式，改完**不能导回 ONNX**。
- 几十亿参数的模型不可能在 3D 里逐权重画出来，得靠「权重块 + 抽样」呈现。
  **权重块在数据模型 / 编译 / 容器 / 3D 显示里都已经是一等公民**（见「权重块」章）：
  3D 里一块就是一张 96×96 封顶的热力图板，能看分布、能点选、能撤销。
  但仍有两个上限：场景里**同时最多画 1024 个块**（更多的只在面板里列出），
  且板子是**缩略图**——要看单个权重得先「展开成连接」（超过 20 万权重会被拦下）。
- **批量连接是 O(n²) 的两两比较**，一次最多 4000 个神经元（超了会明确拒绝）。真要一次连十几万个，
  得上空间网格或 KD 树，现在没做——宁可说清楚，也不让浏览器假死。
- **「按轴分层连接」的层是按坐标分桶的**：桶宽 = 你填的「层厚度」。坐标不是等距排布时，
  分桶结果跟"你心里的层"可能不一样，填之前先看一眼那条轴上的间距。
- **「粗细按权重」「大小按强度」是纯视觉**：不影响数据、不影响编译；两个对比度滑杆也只动显示。
  归一化基准是**当前这张图的参考区间**（大图 p2~p98 / 小图极值），所以同一张图里才有可比性，
  跨工程比没有意义；对比度倍数按绝对值放大，也不是跨图统一的尺度。
- 英文界面覆盖了菜单、图例、属性、按钮、校验报告，各面板的**标题**，以及「算子节点」那一节的正文，
  还有**接口对话框整页**（标记页 + 运行时页的标题 / 按钮 / 开关 / 通道卡片 / 提示）；
  但「权重块 / 剪枝与清理 / 搜索与定位 / 视角书签 / 权重直方图 / 历史与内存 / 随机种子」这几个面板的
  **正文**目前只有中文（它们的文案是直接拼进 HTML 的，要走 `T()` 才能翻，还没做）。
  另外少量**动态拼接**的提示（状态栏长句、校验报告里的统计数字句）仍是中文——
  它们由多段字符串拼出来，词典按整段匹配不到，需要改成带占位符的模板才能真正本地化。
- **接口运行时的几条硬边界**（面板上也写明了，这里再列一遍）：键盘输入**只在前台窗口收得到**——
  操作系统定的，任何软件都改不了；「系统按键」注入到当前前台窗口，软件自己是前台时等于打回自己；
  **UDP / TCP / 串口只有桌面版**能做，浏览器版会明说打不开；「采集按键」记的是 `event.code`（物理键位），
  所以换输入法或键盘布局，绑的仍是同一个物理键。绑定的键被接管时会吞掉这次按键（`preventDefault` +
  `stopImmediatePropagation`），也就是说那个键在软件里从此只喂信号、不再触发快捷键。
- 信号通道**跟着工程文件走**（传输 / 编码 / 信号位 / 周期都存进 `.nforge`），但「已经打开」这个状态不存：
  换一次会话要重新打开一次。收发的**帧数**（rx / tx）同理，是本次运行的计数，不落盘。

## 下一步建议

原型验证的是**交互手感**和**编译链路**，这两件事已经跑通。要变成真正的工业软件，下一步是：

1. **工程化外壳**：Tauri 2 + React + TypeScript，把现在的 3D 编辑器搬进去，
   重计算（校验、拓扑排序、ONNX 编码）放到 Rust 侧，安装包约 10 MB。
2. **表格视图**：3D 看拓扑、表格批量改参数，双视图同步——这是工业软件的标准形态。
3. **模块的参数化**：模块库（把子图封装成可复用模块）已经在做"组 / 宏"这件事；下一步是让同一个
   模块的多个实例可以**共用一组参数**（权值共享的模块级版本）。
4. **真正的界面对接**：现在"接口"只是标记 + 生成输入 / 输出张量；
   下一步做成可绑定真实数据源的端口（文件 / 串口 / OPC UA / HTTP）。
5. **算子节点覆盖更多算子**：`Conv` / 池化 / 归一化 / `Softmax` / `Concat` / `Transpose` / `Reshape`
   这类已经能进来；剩下没覆盖的（`Gather` 这类）仍然明确报错，逐类补上去。

### 大模型：分块加载 + 模型导入（建议的下一块硬骨头）

这两件事是**耦合**的：能产生"大模型"的入口是导入器，而导入器必须顺手把数据切成块，
编辑器才谈得上"只加载附近的部分"。建议一起做，顺序如下：

1. ~~**工程文件升级为分块格式（`.nforge` v3）**~~ **已做**：文件头放索引表，
   每块的神经元区间、连接区间、包围盒、压缩前后字节数都在头里，块体单独 deflate。
   想只解码相机附近的块，索引表已经够用了。
2. ~~**渲染层跟着分块**~~ **已做**：一块一个 `InstancedMesh` / `LineSegments`，
   共享同一份实例缓冲，逐块按包围盒做视锥剔除；包围盒只增不减，所以剔除永远保守。
   12 万神经元 / 60 万连接时，近看只有 1 个球块 + 3 个圆柱块真的提交，
   开 / 关剔除逐像素一致（见「分块渲染」章）。
   ~~**按距离流式载入**~~ **也已做**（见「流式载入」章）：相机靠近才解压，
  打开一份 1.28 MB / 24 块的工程只读了 7,682 B。~~**超预算驱逐**~~ **也已做**：丢远处、保视野内和选中的，
  于是在上限之内可以一直往前飞。~~**按空间分块**~~ **也已做**（见「空间分块」节）：
   `order: "spatial"` 把块界从神经元区间换成空间区域，包围盒平均体积收紧约 65 倍，
   「看向一处」从要解压整张图变成要解压个位数块。~~**权重块区按块读**~~ **也已做**：
   块区按块分段存、每段带包围盒，读的时候只碰相机附近的那几段（那一章「诚实边界」里
   剩下的最后一件已经没有了）。
   另外，现在的三档 LOD 可以直接复用为**块内**的细节等级。
3. ~~**导入器 `tools/import_model.py`**~~ **已做**：ONNX → `.nforge`，
   `Gemm` / `MatMul` / `Add` / 常用激活折成"神经元 + 加权边"，不认识的算子明确报错。
   **权重块已经做进数据模型 / 编译 / 容器**（见「权重块」章）：4096×4096 的矩阵不再需要展开成
   1600 万条边，编译时就是一次 `matmul`，进 `.nforge` 时是独立一段。
   **渲染侧已做**：一块在 3D 里就是一张热力图板（见「权重块」章），能看分布、能点选。
   **导入器折块也已做**：`Gemm` / `MatMul` 默认折成权重块
   （`--blocks auto|always|never` + `--block-min` / `--block-dense`），
   4096×4096 的矩阵不再撑爆边数天花板。权重块**按段存 / 按段读**也已经做了
   （见「流式载入」章与容器章），空间分块同样已经做了。
   **「折平之前长什么样」也已做**：导入来源表写进工程文件头，右上角「结构视图 ⇄」（`F9`）翻页
   看算子图，「模型独有信息」页放 3D 表达不了的东西（聚合块 / 精度变化 / 被跳过的算子）；
   形状还能按拓扑分层 / 直线 / 网格 / 力导向随时重排（见「模型导入」章）。
4. **AI 兜底（二期）**：确定性的算子映射覆盖不到时，再让模型去猜算子语义。
   先做确定性转换器，AI 只做兜底——否则导入结果不可复现，对工业场景是负资产。

**诚实边界**：几十亿参数的模型在浏览器 3D 里不可能逐权重可视化，
必须靠"分块 + 权重块 + 抽样"来呈现。能做到的是**看得出结构、找得到异常、点得进子块**，
而不是把每一个权重都画成一根线。
